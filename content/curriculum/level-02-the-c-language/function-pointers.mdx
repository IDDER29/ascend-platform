A function is code at an address in memory, so you can point at one, the same way you point at an `int`. A **function pointer** holds that address, and calling through it runs whichever function it currently points at. This is how a C library can call *your* code: `qsort` sorts anything because you hand it the function that compares two elements.

## A pointer to a function

The declaration looks odd at first, so read it from the name outwards:

```c
int (*f)(int);
```

`f` is a pointer (`*f`, in brackets), to a function taking an `int` (`(int)`), returning an `int`. The brackets matter: `int *f(int);` would declare a *function* `f` that returns an `int *`.

A function's name, used without calling it, gives its address, so `f = twice;` aims `f` at `twice`, and `f(5)` calls it. Because the full type is hard to read, it's normal to name it once with `typedef`:

```c
typedef int (*IntOp)(int);
```

## qsort and the comparator

`qsort` from `<stdlib.h>` sorts an array of anything. It can't know how to compare your elements, so you give it a comparator:

```c
void qsort(void *base, size_t count, size_t size,
           int (*compare)(const void *, const void *));
```

It calls `compare` with pointers to two elements. The comparator returns a negative number if the first should come first, a positive one if the second should, and 0 if they tie. Because `qsort` works for any type, the pointers are `const void *`; your comparator converts them back to the real type.

<CRun program="c-language/fp-qsort" caption='Sorting both ways with one qsort' />

`(x > y) - (x < y)` is 1, 0 or -1: a safe three-way comparison. `descending` just swaps the arguments of `ascending`, so the same idea sorts both ways.

The comparator's type must match exactly. Here is a comparator that takes `int *` instead of `const void *`:

Since gcc 14, passing an incompatible function pointer is an error. The message spells out both types: the one `qsort` expects (`int (*)(const void *, const void *)`) and the one it got. Calling a function through a pointer of the wrong type is undefined behaviour, so this error saves you from a crash you'd struggle to explain.

## The subtraction trap

Many tutorials write the comparator as one subtraction. Predict the order this prints, then run it. It's compiled with `-fsanitize=undefined`, which reports undefined behaviour as it happens.

<CRun program="c-language/fp-qsort-overflow" caption='return a - b' predict />

<details>
<summary>Check your answer</summary>

The order is wrong: `INT_MIN`, the smallest int, ends up last. `5 - INT_MIN` is 2,147,483,653, just past the largest `int` (2,147,483,647). That overflow is undefined behaviour, and the sanitizer reports it on line 7. In practice it wrapped around to a negative number, so `qsort` was told 5 comes *before* `INT_MIN`, and the sort went wrong without any crash.

Subtraction works only when you know the difference can't overflow. The comparison `(x > y) - (x < y)` is always correct, so use it.

</details>

<KeyIdea>A function pointer stores which function to run. Its type, the parameters and the return type, must match the function exactly, and code that calls through it never needs to know which function it got.</KeyIdea>
