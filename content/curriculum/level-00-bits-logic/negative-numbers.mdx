Binary gave you place values: 8, 4, 2, 1. With them, four bits count from 0 to 15. But programs need negative numbers too: temperatures, bank balances, the distance from here to there going backwards. This lesson shows how computers store them, using a trick so neat that the hardware barely notices.

By the end you'll be able to read and write negative numbers in <b>two's complement</b>, negate a number in two steps, and spot overflow when an answer doesn't fit.

## A minus sign bit isn't enough

The obvious idea: use the top bit as a sign, 0 for plus and 1 for minus, and the other bits for the size. So in 4 bits, 0011 is +3 and 1011 is -3.

It works on paper, but it has two problems. There are now two zeros, 0000 (+0) and 1000 (-0), which is one pattern wasted and an extra case to check everywhere. Worse, the adder you'll build gives wrong answers: 0011 + 1011 should be 3 + (-3) = 0, but plain binary addition gives 1110. Every addition would need special handling for signs.

## The top bit is worth minus

Two's complement keeps the usual place values but makes one change: the <b>top bit is worth minus</b> its usual value. In 4 bits the places are -8, 4, 2, 1.

So 0111 is 4 + 2 + 1 = 7, the largest number. 1000 is -8, the smallest. And 1111 is -8 + 4 + 2 + 1 = -1. Every pattern means exactly one number, and there's only one zero.

With n bits the range is from -2ⁿ⁻¹ to 2ⁿ⁻¹ - 1. For 8 bits that's -128 to 127; for a 32-bit int it's about minus two billion to plus two billion.

<KeyIdea>In two's complement the top bit's place value is negative. Read the rest as usual and add them up.</KeyIdea>

## Flip the bits, add one

To turn a number into its negative, flip every bit and then add 1. Take 5, which is 0101. Flip every bit: 1010. Add 1: 1011. Check it: -8 + 2 + 1 = -5. It works the other way too: flip 1011 to 0100, add 1, and you're back at 0101, which is 5.

## The same adder does everything

Here's why every computer uses this: ordinary binary addition just works. Add 3 and -5: 0011 + 1011 = 1110, and 1110 is -8 + 4 + 2 = -2. Correct, with no special cases. Subtraction comes free as well: A - B is A + (-B), and -B is "flip and add 1".

So a CPU needs one adder for both adding and subtracting, signed and unsigned. The bits don't change; only how you read the answer does.

<KeyIdea>Two's complement lets one ordinary adder handle negative numbers and subtraction, which is why every modern computer uses it.</KeyIdea>

## Overflow: when the answer doesn't fit

Four bits hold -8 to 7, so some answers simply don't fit. Add 7 + 1: 0111 + 0001 = 1000, which reads as -8. The sum ran off the top of the range and came back round at the bottom. That is <b>overflow</b>.

Hardware doesn't stop you; it just wraps. In C, overflowing an unsigned number is defined to wrap like this, but overflowing a signed int is undefined behaviour, which you'll meet again in the C path. Either way, the first defence is knowing your range.
