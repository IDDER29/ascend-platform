An object file is the assembler's output: machine code that isn't finished. In this lesson you'll open one and find three things inside it: <b>sections</b>, <b>symbols</b> and <b>relocations</b>.

By the end you'll be able to say where each part of a C file lands, read nm output, and explain the gaps the linker will fill. The example is main.o, compiled with `gcc -c main.c` from this section's program (gcc 15.2, x86-64 Linux); other systems print slightly different details.

## Sections: code and data kept apart

An object file is divided into <b>sections</b>, one per kind of content. `objdump -h main.o` lists them; here are the first four:

```
Sections:
Idx Name          Size      VMA               LMA               File off  Algn
  0 .text         00000094  0000000000000000  0000000000000000  00000040  2**0
                  CONTENTS, ALLOC, LOAD, RELOC, READONLY, CODE
  1 .data         00000004  0000000000000000  0000000000000000  000000d4  2**2
                  CONTENTS, ALLOC, LOAD, DATA
  2 .bss          0000000c  0000000000000000  0000000000000000  000000d8  2**3
                  ALLOC
  3 .rodata       0000000d  0000000000000000  0000000000000000  000000d8  2**3
                  CONTENTS, ALLOC, LOAD, READONLY, DATA
...
```

The sizes are in hex, and each one matches something in main.c:

<TruthTable caption='Where main.c went' rowsJson='[["section", "size", "what it holds", "from main.c"], [".text", "0x94 = 148 bytes", "machine code", "main"], [".data", "4 bytes", "variables with a starting value", "int count = 3;"], [".bss", "0xc = 12 bytes", "variables that start at zero (no bytes stored)", "int results[3];"], [".rodata", "0xd = 13 bytes", "read-only data", "the text squares: (9 bytes) and the format for each number (4 bytes)"]]' />

.bss has no CONTENTS flag: the file only records "12 bytes, all zero", and the space is made when the program is loaded. Keeping read-only data apart means it can be loaded where writing to it is forbidden.

<KeyIdea>Sections sort a file's bytes by kind: code, data with a value, zeroed data, read-only data. Each will be loaded with its own rules.</KeyIdea>

## Symbols: names the linker can see

A <b>symbol</b> is a name the object file shares with the outside: a function or global variable it defines, or one it needs. `nm` lists them. For square.o:

```
0000000000000000 T square
```

And for main.o:

```
0000000000000000 D count
0000000000000000 R greeting
0000000000000000 T main
                 U printf
                 U puts
0000000000000000 B results
                 U square
```

The letter says where each symbol lives: T in .text (code), D in .data, B in .bss, R in read-only data. U means <b>undefined</b>: main.o uses the name but doesn't contain it. Every U must be matched by a definition somewhere else, or the program can't be built.

One surprise: `puts`. main.c never mentions it. gcc noticed that `printf("%s\n", greeting)` prints a string and a newline, which is exactly what `puts` does, and called that instead. The object file shows what the compiler really did, not what the source says.

## Relocations: notes for the linker

`objdump -d -r main.o` disassembles the code and shows the gaps. Here is the call to square:

```
  2e:	89 c7                	mov    %eax,%edi
  30:	e8 00 00 00 00       	call   35 <main+0x35>
			31: R_X86_64_PLT32	square-0x4
```

`e8` is x86's call instruction, followed by four bytes of where to go. They're all zero, because when main.c was compiled nobody knew where square would be. Instead the assembler left a <b>relocation</b>, the line under it: at byte 0x31, put the address of square (written the way this kind of call needs it). There's one for every use of an outside name or a global: `greeting`, `results`, `puts`.

It's the same problem a two-pass assembler solves for labels, one step later: labels in another file can't be known until all the files meet.

<details>
<summary>Check your answer: which section would const int limit = 10; at the top of a file go in, and which would static int seen; inside a function go in?</summary>

`limit` has a value and can't change: .rodata (nm shows R). `seen` lives for the whole program and starts at zero: .bss. gcc 15 lists it as `b seen.0`: a lowercase b because static makes it private to the file, and `.0` added so it can't clash with another `seen`.

</details>
