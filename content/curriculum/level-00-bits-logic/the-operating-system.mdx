On the tiny CPU, one program owns the whole machine. It can read any box, write any port and run forever. A real computer runs dozens of programs at once, from many authors, on the same hardware. Something has to be in charge. That's the **operating system**.

By the end you'll be able to say what the OS does for a program, and why programs ask it instead of touching the hardware themselves.

## Apps and the kernel

An **app** is a program that does a job for you: an editor, a browser, a game. The **kernel** is the core of the operating system: the program the bootloader loaded, which runs from startup to shutdown, controls the hardware, and serves every app.

An operating system is the kernel plus the programs that come with it: the desktop, the file manager, the settings app and many background services. Those are apps too. They just come in the box.

<KeyIdea>Apps do jobs for people; the kernel runs the machine for the apps. Apps get hardware only through the kernel.</KeyIdea>

## One interface for every device

There are thousands of models of SSD, keyboard and network card, each with its own controller and commands. The kernel has a **driver** for each: the code that knows how to talk to that model. Apps never see them. An app says "write these bytes to notes.txt" or "show this text", and the kernel and its drivers do the rest.

That gives three things at once:

- **Simplicity**: one request works on any hardware.
- **Safety**: the kernel checks every request, so a buggy or hostile app can't scribble over another's files or take over the network card.
- **Sharing**: the kernel decides whose turn it is when two programs want the same device.

## The OS is software too

The kernel isn't magic. It's a program, written mostly in C, compiled to machine instructions, and run by the same CPU as everything else. What makes it different is that the hardware lets it do things apps can't: the next lesson shows how the CPU itself enforces that line.

The tiny CPU has no operating system. Every program is the only program, with the whole machine to itself, which is exactly why it's a good machine to learn on, and exactly why real computers need more.
