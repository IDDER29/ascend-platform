In Foundations you saw an if turn into a compare and a conditional jump. In C you write the decision, and the compiler makes the jumps. This lesson covers the two ways to choose: `if` chains and `switch`.

## Choosing one branch

An `if` runs its block when the condition is true. `else if` adds another test, tried only if every test before it failed, and `else` catches everything left. Exactly one branch of the chain runs.

<CRun program="c-basics/grade" caption='Grading four scores' />

95 passes `s >= 90`, so it gets an A, and the other tests are never tried, even though 95 is also above 80 and 50. Order matters: if `s >= 50` came first, every passing score would land there. Put the strictest test first.

The `for` loop and the array `{95, 82, 64, 40}` just feed four scores through the same chain; loops come next lesson and arrays later in C Basics.

## What counts as true

C has no separate true and false for conditions: zero is false, and every other value is true.

<CRun program="c-basics/truthy" caption='Which numbers are true?' predict />

<details>
<summary>Check your answer</summary>

Only 0 is false. 1, -1 and 42 are all true. So `if (count)` means "if count isn't zero", which you'll see a lot in C code. It also means a mistake such as `if (x = 5)` compiles: the assignment gives 5, which is true.

</details>

## Switch and the missing break

`switch` compares one integer value against fixed `case` labels and jumps to the match. `break` leaves the switch; `default` catches values with no case. Several labels can share one block, as 6 and 7 do here:

<CRun program="c-basics/switch-days" caption='Days of the week' />

`switch` is a jump to a label, not a set of separate branches. Without a `break`, execution just continues into the next case's statements. Predict what this prints for `difficulty = 2`.

<CRun program="c-basics/switch-fallthrough" caption='Three missing breaks' predict />

<details>
<summary>Check your answer</summary>

```
medium
hard
unknown
```

The switch jumps to `case 2:`, prints `medium`, and with no `break` falls through into `case 3:` and `default:` too. gcc's `-Wextra` warns about each fall-through, and the warnings point at the exact statements. The fix is a `break;` after each `printf`. Falling through on purpose is occasionally useful; then say so with a `/* fall through */` comment, which also silences the warning.

</details>

<KeyIdea>An if chain runs the first branch whose condition is nonzero. A switch jumps to the matching case and runs on until a break: never leave one out by accident.</KeyIdea>

## The dangling else

Without braces, an `else` belongs to the nearest `if` above it, whatever the indentation says. Read this program and predict its output, then run it.

<CRun program="c-basics/dangling-else" caption='Whose else is it?' predict />

<details>
<summary>Check your answer</summary>

Only `done`. The indentation suggests the `else` belongs to `if (a > 0)`, but C attaches it to the inner `if (b > 0)`. Since `a > 0` is false, the whole inner if, else included, is skipped, and "a is not positive" is never printed. gcc warns: "suggest explicit braces to avoid ambiguous 'else'".

The fix, and the habit, is braces on every branch:

```c
if (a > 0) {
    if (b > 0) {
        printf("both positive\n");
    }
} else {
    printf("a is not positive\n");
}
```

</details>
