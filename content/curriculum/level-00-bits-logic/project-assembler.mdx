You're the assembler. In each lab, fill in what each pass works out; every cell is checked against the real assembler as you type. Addresses can be written as hex (0x0A or 0A) or decimal (10). Bytes are two hex bytes, like `08 03`.

You'll need the opcodes. Here are the ones used below; byte0 is `opcode << 3 | Rd << 1`.

A register other than R0 adds `Rd << 1` to byte0: R1 adds 2, R2 adds 4, R3 adds 6.

## Part 2: A forward call

This program calls a subroutine defined after it. Assemble it.

<AssemblerLab caption='Assemble a program with a forward call' programJson='["LDI R1, 2", "CALL show", "CALL show", "HALT", "show: OUT R1", "INC R1", "RET"]' passJson='both' />

<details>
<summary>Check your answer</summary>

Pass one: 0x00, 0x02, 0x04, 0x06, 0x08, 0x0A, 0x0C, and `show` = 0x08.

Pass two: `0A 02` (LDI with R1: 08 + 2), `98 08`, `98 08`, `A8 00`, `82 00` (OUT R1), `B2 00` (INC R1), `A0 00`.

When pass two reaches the first CALL, `show` is already in the label table. A one-pass assembler would have had to leave a gap and come back.

</details>

## Part 3: Find the assembler bug

A classmate's assembler produced these bytes for the program in part 2:

<TruthTable caption='Bytes from a buggy assembler' rowsJson='[["address", "source", "bytes"], ["00", "LDI R1, 2", "0A 02"], ["02", "CALL show", "98 04"], ["04", "CALL show", "98 04"], ["06", "HALT", "A8 00"], ["08", "show: OUT R1", "82 00"], ["0A", "INC R1", "B2 00"], ["0C", "RET", "A0 00"]]' />

What did it get wrong, and what would the program do?

<details>
<summary>Check your answer</summary>

Both CALLs say 04 instead of 08. `show` is the fifth instruction, index 4, and the assembler used that index instead of the byte address: each instruction is two bytes, so the fifth starts at 8. The program would call 0x04, which is the second CALL itself, calling itself again and again until the stack overflows. One wrong multiplication in pass one breaks every jump to a label.

</details>

## Part 4: Write the procedure

Write the assembler as numbered steps a program could follow, with no "and then you work it out". Then compare with this one.

<details>
<summary>Check your answer</summary>

Pass one:
1. Set the location counter to 0 and the label table to empty.
2. For each line: remove the comment. If it starts with `name:`, record name = location counter. If an instruction is left, add 2 to the location counter.

Pass two:
1. Set the location counter to 0.
2. For each line with an instruction: look up its opcode and format; read its register and operand, replacing a label with its address from the table; write `byte0 = opcode << 3 | Rd << 1` and `byte1` by format at the location counter; add 2.
3. Report an error for an unknown instruction, a missing label or an operand out of range.

That's a complete assembler. The one this site uses (`assemble` in its source) is these steps plus error messages.

</details>
