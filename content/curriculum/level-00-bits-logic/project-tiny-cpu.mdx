This is where everything in Build a CPU comes together. There are three programs, all for the tiny CPU you've been using. For each one, do it in this order:

1. <b>Predict.</b> Read the program and write down what the display will show.
2. <b>Step.</b> Press Step one instruction at a time and watch A, the flags and memory.
3. <b>Compare.</b> If the result isn't what you predicted, find the exact step where your picture and the machine's differed.

Don't press Run first. The point is to be right before you look.

## Part 1: Multiply with a loop

The tiny CPU can add but not multiply. So this program multiplies 6 by 3 the way you'd do it by hand: add 6 three times.

- What will the display show?
- What will addresses 13 and 15 hold when it halts?
- How many instructions will run in total? (Hint: count one pass of the loop, then the end.)

Predict: which numbers appear on the display, and what is in A at the end?

<details>
<summary>Check your prediction</summary>

The display shows 0, 64, 128, 192. The next ADD gives 256, which needs 9 bits. A wraps to 0 and the carry flag is set, so JC jumps to HLT. A ends at 0, not 256. That is overflow, now steering the program.

## Part 3: Fix the bug

This program is meant to show 5, 4, 3, 2, 1 and stop. Run it and see what it does instead.

<TinyCpu caption='Part 3: a countdown that never ends' programJson='["LDI 5", "OUT", "SUB 15", "JZ 0", "JMP 1", "HLT"]' dataJson='{"15": 1}' />

It shows 5, 4, 3, 2, 1, then starts again at 5 and never halts; the simulator stops it after 256 steps. Find the one instruction that is wrong before reading on.

<details>
<summary>Check your prediction</summary>

The bug is JZ 0 at address 3. When the count reaches 0, it jumps back to address 0, where LDI 5 restarts everything. HLT is at address 5, so the jump should be JZ 5:

<TinyCpu caption='Part 3, fixed' programJson='["LDI 5", "OUT", "SUB 15", "JZ 5", "JMP 1", "HLT"]' dataJson='{"15": 1}' />

</details>

A jump to the wrong address is one of the most common bugs in any language. In C it looks like a loop condition that never becomes false.
