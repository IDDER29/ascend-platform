In Foundations you met variables as named boxes in memory, and types as widths. C makes both explicit: every variable is declared with a type before it's used, and the type fixes how many bytes the box has and what its bits mean.

## Declaring and using variables

A declaration gives a type and a name, and can give a first value (an **initialiser**):

<CRun program="c-basics/declare-and-use" caption='Three variables, three types' />

- `int apples = 7;` is a whole number. `apples = apples + 5;` reads the box, adds 5, and writes it back, the update you stepped through in Foundations.
- `double price = 0.45;` is a number with a fractional part. `%.2f` prints it with two decimals.
- `char grade = 'B';` is one character in single quotes. It's stored as a small number, its character code: `%c` prints it as a letter and `%d` as the number 66.

The format in `printf` must match the type: `%d` for `int`, `%f` for `double`, `%c` for `char`. You'll see in Reading compiler errors what happens when it doesn't.

Always give a variable a value before you read it. A local variable declared without an initialiser holds whatever bytes were already in its box, and reading it is a bug that gcc can only sometimes warn about.

## Every type has a size

`sizeof` gives the size of a type, or of a variable, in bytes. `%zu` is the format for the size type it returns.

<CRun program="c-basics/sizes" caption='How big is each type here?' />

These are the sizes on x86-64 Linux, where this was run. C itself only promises minimums: a `char` is always exactly 1 byte, an `int` is at least 2 bytes and is usually 4, and a `long` is 8 bytes here but 4 on 64-bit Windows. When a size really matters (a file format, a network packet), C has exact types like `int32_t` and `uint8_t` in `<stdint.h>`.

The size fixes the range. `<limits.h>` names the edges:

<CRun program="c-basics/ranges" caption='The edges of each range' />

A 4-byte `int` is two's complement, as in Foundations, so it runs from -2,147,483,648 to 2,147,483,647. The `unsigned` version gives up negative numbers to reach twice as high.

<KeyIdea>A C type says how many bytes a value takes and how to read its bits. sizeof tells you the size; limits.h tells you the range.</KeyIdea>

## Going past the range

What happens when a value doesn't fit? Predict both lines before you run this.

<CRun program="c-basics/wrap" caption='Past the edge' predict />

<details>
<summary>Check your answer</summary>

`4`, then `4294967295`. Unsigned types wrap around, exactly like the byte arithmetic in Foundations: 250 + 10 = 260, which doesn't fit in an `unsigned char` (0 to 255), so 256 is taken off, leaving 4. And 0 - 1 in an `unsigned int` wraps to the largest value, 2³² - 1.

Signed types are different: overflowing an `int` (going past `INT_MAX`) is **undefined behaviour** in C. The language doesn't promise wrapping or anything else, and compilers do take advantage of that. The C Language and The C Contract come back to it; for now, keep `int` values well inside their range.

</details>

## Doubles are close, not exact

`double` stores numbers in binary floating point, and most decimal fractions, 0.1 included, can't be written exactly in binary (you saw why in Foundations). Predict all three lines.

<CRun program="c-basics/float-precision" caption='Is 0.1 + 0.2 equal to 0.3?' predict />

<details>
<summary>Check your answer</summary>

`%f` rounds to six decimals and shows `0.300000`, which hides the problem. `%.17f` shows the stored value, `0.30000000000000004`, so `a == 0.3` is false and the program prints `not equal`. Never compare `double` results with `==`; check whether they're close enough instead, such as `fabs(a - 0.3) < 1e-9`. And never use `double` for money: count whole cents in an integer.

</details>
