The memory board is 256 one-byte boxes, numbered 0x00 to 0xFF. You control it the way a CPU does, with four signals: an **address**, **data in**, **write enable**, and the clock **tick**. Data out always shows the box the address selects.

For each part, plan your ticks first, then do them, then open "Check your answer".

## Part 1: One write, one box

Write 42 into box 5. Then tick once more with write enable off. Watch the timeline: which boxes changed on each tick?

<MemoryBoard caption='Write one box' sizeJson='16' goalJson='{"5":42}' />

<details>
<summary>Check your answer</summary>

Address 5, data 42, write enable on, Tick: the timeline says "changed box 5", and only that box turns lime. The second tick, with write enable off, changes nothing. Data out shows 42 whenever the address is 5, with or without write enable: reading needs no tick.

</details>

## Part 2: Fill a row

On the full 256-byte board, store 1, 2, 3, 4 in boxes 0x80 to 0x83 (128 to 131), without touching anything else.

<MemoryBoard caption='The full board' sizeJson='256' goalJson='{"128":1,"129":2,"130":3,"131":4}' />

<details>
<summary>Check your answer</summary>

Four ticks, each with write enable on and a different address and data: (128, 1), (129, 2), (130, 3), (131, 4). One write per tick: a memory like this can change only one box at a time. The board says "Done" only if no other box changed, so a stray write on the wrong address would show.

</details>

## Part 3: Copy a value

Box 0x10 (16) holds 99. Copy it into box 0x40 (64). You can only use the four signals: there's no "copy" button.

<MemoryBoard caption='Copy box 16 to box 64' sizeJson='256' startJson='{"16":99}' goalJson='{"16":99,"64":99}' />

<details>
<summary>Check your answer</summary>

Set the address to 16 and read data out: 99. Then set the address to 64, data in to 99, write enable on, and Tick. Memory can't move a value by itself. Something outside it has to read and then write, and in a computer that something is the CPU, using exactly these two steps for every LDA and STA.

</details>

## Part 4: A board with a fault

This board has a faulty decoder. Write 7 to box 0x22 (34) and watch the timeline. Then try a few other addresses. Which address bit does the decoder ignore?

<MemoryBoard caption='A faulty board' sizeJson='256' faultJson='{"ignoreAddressBit":0}' />

<details>
<summary>Check your answer</summary>

Writing to 34 (0x22) changes boxes 34 and 35 together. Writing to 35 does the same. 34 is 0010 0010 and 35 is 0010 0011, which differ only in bit 0, the lowest bit. Every write lands on a pair of boxes that differ only in bit 0, so the decoder ignores bit 0. In real hardware this could be a broken wire from that address line. You found it from the timeline alone, without opening the box.

</details>

<KeyIdea>Memory only does what its signals say, on the tick, to the box the decoder picks. Two boxes changing at once means the decoder is picking two.</KeyIdea>
