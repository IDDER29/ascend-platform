In the last lesson, R1 held an address and `LDR R0, [R1]` read the box it named. That register was a <b>pointer</b>: a value that refers to a place in memory, rather than being the data itself.

By the end you'll be able to tell a pointer from what it points to, follow one, and say why functions need them.

## Follow the pointer

A pointer can be stored in memory like any other value. Here, box 0x80 holds 133 (0x85), and box 133 holds 42. Read as a pointer, box 0x80 says "the value you want is in box 133".

This program should output 42, the value the pointer refers to. It outputs 133: it prints the pointer instead of following it.

<TinyCpu2 editable caption='Follow a pointer' programJson='["LDA R0, [0x80]", "OUT R0", "HALT"]' dataJson='{"128":133,"133":42}' goalJson='{"out":[42]}' />

<details>
<summary>Check your answer</summary>

```
LDA R1, [0x80]    ; R1 = the pointer: 133
LDR R0, [R1]      ; R0 = the box it points to: 42
OUT R0
HALT
```

Two reads: one to get the address, one to get what's there. Mixing them up (printing the address, or using a value as an address) is the most common pointer bug there is.

</details>

<KeyIdea>A pointer is a value that says where. Following it, called dereferencing, reads or writes what's there.</KeyIdea>

## Pointers in C

C writes the two operations as `&` (the address of a variable) and `*` (follow a pointer):

```c
#include <stdio.h>

void set_to_seven(int *p) {
    *p = 7;
}

int main(void) {
    int x = 5;
    int *p = &x;
    printf("%d\n", *p);
    set_to_seven(p);
    printf("%d\n", x);
    return 0;
}
```

```
5
7
```

`int *p = &x;` makes p refer to x. `*p` reads x through p, and `*p = 7` writes x through p.

A C pointer is best thought of as "refers to this object", not as a raw number for a physical place in the chips. On a modern computer the addresses a program sees are translated by the operating system (you'll see how in The Complete System), and C has rules about which pointers are allowed. On the tiny CPU, where an address really is a box number, the two pictures match.

## Pointers let functions reach back

A function gets copies of its arguments, so a function given `x` gets a copy and can't change the original. Given a pointer to x, it gets a copy of the pointer, and that copy still refers to x's box. This is how a C function swaps two variables:

```c
#include <stdio.h>

void swap(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}

int main(void) {
    int x = 5, y = 9;
    swap(&x, &y);
    printf("%d %d\n", x, y);
    return 0;
}
```

```
9 5
```

It's the same three-step swap from the variables lesson, done through pointers to the caller's boxes.
