In maths, `x = x + 1` is a contradiction: no number equals itself plus one. In a program it's one of the most common lines there is. The difference is that `=` in a program doesn't state a fact. It's an order: work out the right-hand side, then put the result in the box on the left.

By the end you'll be able to trace any assignment as reads and writes of memory, and avoid the classic swap bug.

## A variable is a named box

When the translator sees `var x = 0;`, it picks a box in memory for x (the first variable gets 0x80, the next 0x81, and so on) and stores 0 there. From then on, the name x means "the box at 0x80". The lab shows each variable's address next to its value.

## Read, add, write back

The translator turns `x = x + 1;` into:

<TruthTable caption='x = x + 1, as instructions' rowsJson='[["instruction", "what it does"], ["LDA R0, [0x80]", "read: copy x into R0"], ["LDI R1, 1", "get the number 1"], ["ADD R0, R1", "add: R0 is now x + 1"], ["STA R0, [0x80]", "write: put R0 back into x"]]' />

Read, add, write back. Nothing happens to x until the last step, and after it the old value is gone. The right-hand side is worked out first, using x's old value; only then does x change.

<KeyIdea>An assignment is an order, not an equation: work out the right side, then overwrite the box on the left.</KeyIdea>

This program should leave x at 3. It only adds once. Make it 3.

## The swap trap

This program is meant to swap a and b, so a ends as 9 and b as 5. Run it and look at the values.

<TranslatorLab caption='Swap a and b' startJson='["var a = 5;","var b = 9;","a = b;","b = a;"]' goalJson='{"vars":{"a":9,"b":5}}' />

<details>
<summary>Check your answer</summary>

Both end as 9. `a = b;` overwrites a's box with 9, and the 5 is gone for good; `b = a;` then copies that 9 back. The fix is a third box to keep the old value:

```
var a = 5;
var b = 9;
var t = 0;
t = a;
a = b;
b = t;
```

Seeing a variable as a box that holds one value at a time is exactly what makes this bug obvious.

</details>
