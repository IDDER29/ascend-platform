Every gate you've met so far, and every circuit built from them, has the same property: the output is worked out from the inputs right now, and from nothing else. That's enough to add two numbers. It isn't enough to build a computer, because a computer also has to remember.

By the end you'll be able to say what makes a circuit combinational, show why it can't remember anything, and tell which jobs need memory.

## Outputs from inputs only

A circuit made of gates, with every wire flowing forward from the inputs to the outputs, is called <b>combinational</b>. Its outputs are a fixed function of its inputs: the same inputs always give the same outputs.

The half-adder is one. Put in A = 1 and B = 1 and you get sum 0, carry 1. It doesn't matter what you put in a second ago, or a year ago. Its whole behaviour fits in a truth table, and the table has one row per input combination:

<KeyIdea>A combinational circuit is a truth table made of gates. Same inputs in, same outputs out, every time.</KeyIdea>

## What a truth table cannot hold

Now imagine a doorbell counter: one button, and a display showing how many times the button has been pressed. Try to write its truth table.

The input is just the button: 0 or 1. So the table has two rows. But after one press the display should show 1, and after five presses it should show 5, and in both cases the button is now 0. Same input, different output. No truth table can do that, so no combinational circuit can.

The count is <b>state</b>: something the circuit must remember about the past. You met state with the turnstile, which needed to know whether it was locked. Combinational logic has no place to keep it.

## Where memory comes from

Memory needs one new idea: a loop. If a gate's output is wired back into its own input, the circuit can hold a value after the input that set it has gone. That kind of circuit is a <b>latch</b>, and you'll build one in the State & Memory course.
