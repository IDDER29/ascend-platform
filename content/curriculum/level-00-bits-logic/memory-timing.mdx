You know what memory is: numbered boxes, picked by a decoder. This lesson is about <b>when</b> things happen in it. A memory that changed whenever a wire flickered would be useless, so real memory follows strict timing rules, set by the clock.

By the end you'll be able to say exactly when a box changes, why reading is different from writing, and how memory is wired up ready for a CPU to use.

## Writes wait for the tick

A memory box is a register, and a register only changes on a clock tick when its load input is on. Memory adds one more signal in front of that: <b>write enable</b>. On each tick:

- if write enable is on, the box the address picks takes in the byte on <b>data in</b>;
- if write enable is off, nothing changes at all.

Every other box keeps its value, whatever is on the wires. The decoder only sends the load signal to one box.

## Reads follow the address

Reading works differently. <b>Data out</b> always shows the box the address picks, through a multiplexer. There is no tick: change the address and, after a short delay while the multiplexer's gates settle, the new box's value appears.

<TruthTable caption='Reading and writing, side by side' rowsJson='[["", "reading", "writing"], ["needs a tick?", "no", "yes"], ["needs write enable?", "no", "yes, on"], ["what changes", "only data out", "the one box the address picks"], ["when it shows up", "a short delay after the address changes", "at the tick"]]' />

That short delay matters. A CPU that asks for a byte must wait long enough for it to arrive before it uses it. That delay is one of the things that limits how fast the clock can tick.

## Steady before and after the tick

A write only works if the address and data are steady at the right moment. If the address is still changing when the tick arrives, the decoder may not have settled on one box yet, and the wrong box, or two boxes, could take the data.

So every memory chip states two small times:

- <b>setup time</b>: how long before the tick the address and data must already be steady;
- <b>hold time</b>: how long after the tick they must stay steady.

The clock makes this easy to honour. The CPU changes its signals just after one tick, they settle during the gap, and the memory acts on the next tick. As long as the gap is longer than the settling time, every write lands where it should.

<KeyIdea>Signals settle between ticks; memory acts on the tick. The clock gives every wire time to be ready.</KeyIdea>

## A small memory system

To be ready for a CPU, memory gets a few registers around it. This is how the tiny CPU in this path is wired:

- a <b>memory address register</b> holds the address, so it stays steady while the CPU does other things;
- <b>data in</b> carries the byte to write, from the bus;
- <b>data out</b> puts the chosen box's byte back on the bus when the CPU reads;
- <b>write enable</b> comes from the CPU's control unit, switched on only for an instruction that stores.

To read box 14, the CPU loads 14 into the memory address register on one tick; data out shows box 14 shortly after, and the CPU loads it into a register on the next tick. To write, it loads the address, puts the byte on data in, and switches write enable on for one tick.

A write to box 4 also changes box 5, and a write to box 6 also changes box 7. In binary, 4 is 0100 and 5 is 0101: they differ only in the lowest bit. The decoder is ignoring that bit, so it can't tell the two boxes apart and both take the write. In a real chip this is a broken or unconnected address line.
