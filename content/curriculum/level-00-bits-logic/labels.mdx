Loops and decisions are jumps, and a jump needs to know where to go. On the tiny CPU that's an address: JNZ 0x02 means "if Z is 0, the next instruction comes from address 0x02". Writing those numbers by hand works, until the program changes.

By the end you'll be able to name places in a program with labels, explain why that matters, and say what the assembler has to do with them.

## Jumps need addresses

Each instruction of the tiny CPU version 2 takes two bytes, starting at address 0x00. So the first instruction is at 0x00, the second at 0x02, the third at 0x04, and so on. This countdown jumps back to the OUT at address 0x02:

<TruthTable caption='A countdown with a written address' rowsJson='[["address", "instruction", "what it does"], ["0x00", "LDI R0, 3", "R0 = 3"], ["0x02", "OUT R0", "show R0"], ["0x04", "DEC R0", "R0 = R0 - 1, and set Z"], ["0x06", "JNZ 0x02", "if R0 is not 0, go back to 0x02"], ["0x08", "HALT", "stop"]]' />

It shows 3, 2, 1 and stops. To write JNZ 0x02 you had to count the bytes yourself.

## A label names an address

A <b>label</b> is a name you put in front of an instruction, followed by a colon. The label stands for that instruction's address, and you can use it anywhere an address goes:

<TinyCpu2 caption='The same countdown, with a label' programJson='["LDI R0, 3", "loop: OUT R0", "DEC R0", "JNZ loop", "HALT"]' />

Here `loop` means 0x02, so JNZ loop is exactly the same instruction as JNZ 0x02: the same two bytes in memory. The CPU never sees the word "loop". It only exists in the source code, for people.

<KeyIdea>A label is a name for an address. The assembler swaps every label for its number; the CPU only ever sees the number.</KeyIdea>

## Why hard-coded addresses break

Programs change. Say you need a new first instruction, LDI R1, 9. Every instruction after it moves up by two bytes, but a jump written as JNZ 0x02 still says 0x02. Address 0x02 now holds LDI R0, 3, so every trip round the loop resets R0 to 3.

As written, it shows 3 over and over, until the simulator stops it after 1,000 steps: the jump goes back to LDI R0, 3 every time. The fix is a label on the OUT line, `loop: OUT R0`, and `JNZ loop`. The label now means 0x04, and if you add more instructions later it moves with them.

## Labels the assembler must resolve

A label can be used before the line that defines it. In this version, `JZ done` jumps forward to a label further down:

<TinyCpu2 caption='A jump forward to a label' programJson='["LDI R0, 3", "loop: OUT R0", "DEC R0", "JZ done", "JMP loop", "done: HALT"]' />

When the assembler reaches JZ done, it hasn't seen `done:` yet, so it can't know the number. The next lesson shows how it solves that: it reads the program twice.

<KeyIdea>Write names, not numbers. Turning names into numbers is the assembler's job, and it never miscounts.</KeyIdea>
