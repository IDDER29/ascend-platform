Inside a computer, and between computers, bits travel as something physical: a voltage, light, a radio wave. Nothing physical is perfectly clean. In this optional project you send a short message down a noisy line and work out how the receiver can still get it right.

This is a preview of communications, not an electronics course: the line here is a simple model with two voltages, 0 V for a 0 and 5 V for a 1, and random noise added to each.

## Part 1: Where to draw the line

The receiver reads each voltage and decides: at or above its **threshold** is a 1, below is a 0. This receiver's threshold is set badly. Move it until "HI" arrives with no wrong bits.

<ChannelLab caption='Set the receiver' messageJson='"HI"' noiseJson='1' thresholdJson='4.2' seedJson='4' goalJson='{"errors":0}' />

<details>
<summary>Check your answer</summary>

At 4.2 V, any 1 that the noise pushes down below 4.2 V is read as 0, and three bits are misread. Anywhere from about 2.3 V to 3.3 V works here. The best choice is halfway, 2.5 V, because it leaves the same margin for a 0 pushed up as for a 1 pushed down.

That's why digital signals are so robust: as long as the noise is smaller than half the gap between the two levels, every bit is read correctly, however blurred it is.

</details>

## Part 2: More noise

This line lets you change the noise too. Keep the threshold at 2.5 V and slowly raise the noise. Before you do, predict roughly where the first misread appears. Then try a longer message.

<ChannelLab noiseAdjustable caption='Turn up the noise' messageJson='"DATA"' noiseJson='0.4' thresholdJson='2.5' seedJson='13' />

<details>
<summary>Check your answer</summary>

With little noise, nothing is misread: the voltages stay far from 2.5 V. On this line the first misread appears at about 1 V of noise; by 2 V, eight of the 32 bits are wrong. There's no sharp cut-off, because noise is random: big pushes are rare, not impossible. More bits sent means more chances for one of those rare pushes, so longer messages need protection even on a good line.

</details>

## Part 3: Codes that fight back

This line is too noisy for any threshold to save. Try each code and watch the counts below the chart.

<ChannelLab caption='Choose a code' messageJson='"HI"' noiseJson='1.3' thresholdJson='2.5' seedJson='53' codingsJson='["none","parity","repeat3"]' goalJson='{"errors":0}' />

<details>
<summary>Check your answer</summary>

- **No code:** three data bits arrive wrong, and the receiver has no idea.
- **Parity bit per byte:** the sender adds one bit to each byte so the number of 1s is even. The receiver flags the first byte, because its count came out odd. It knows that byte is damaged, but not which bit, so it can't fix it; it would have to ask for that byte again. Two flips in one byte would cancel out and slip through unnoticed.
- **Send each bit 3 times:** the receiver takes a majority vote of each three. A single flip in a trio is outvoted, so the message arrives intact. The cost is three times as many bits on the line.

Real systems choose from the same trade-off, with cleverer codes: networks detect errors with checksums and resend, while storage and memory chips correct them with error-correcting codes.

</details>

## Part 4: Agreeing first

Write down everything the sender and the receiver must agree on before the first bit is sent, using this lab as your example.

<details>
<summary>Check your answer</summary>

- **The two levels:** that 0 V means 0 and 5 V means 1 (and not the other way round).
- **The threshold** the receiver uses, which depends on the levels.
- **Timing:** when each bit starts and ends, so the receiver samples once per bit.
- **The code:** none, parity or three copies, and where code bits go.
- **The meaning of the bits:** that each 8 bits are a character code, and which code.

None of this is in the signal itself. It's an agreement, a protocol, made in advance. This is the same idea that returns when you study networks.

</details>

<KeyIdea>Two well-separated states make bits survive noise; a threshold between them reads the bits back; codes detect or correct the flips that still get through. All of it only works because both ends agreed first.</KeyIdea>
