In Assembly Language you used CALL and RET, and watched the return address go onto the stack. Real programs call functions all the time, often from inside other functions, so the stack is always busy. This lesson puts a name on what each call leaves there.

By the end you'll be able to trace calls on the stack and say what a real compiler keeps in each call's frame.

## A function called twice

This program should call add3 twice, starting from 1, and output 7. The subroutine is empty, so it outputs 1. Fill it in, then step through and watch SP and the stack area of memory.

<details>
<summary>Check your answer</summary>

```
add3: ADDI R0, 3
RET
```

Each CALL pushes a different return address: the first saves 0x04 (the second CALL), the second saves 0x06 (the OUT). SP drops to 0xEF during each call and comes back to 0xF0 after each RET. One piece of code, used twice, and each use knows where to go back to.

</details>

## One frame per unfinished call

The space one call uses on the stack is its <b>stack frame</b>. On the tiny CPU a frame is just the return address, plus anything the routine PUSHes to save. In real languages a frame also holds the call's arguments (when they don't fit in registers) and its <b>local variables</b>.

Because every call gets its own frame, a function can be running several times at once, each with its own locals: when a function calls itself (recursion), or when one call is waiting for another to finish.

<KeyIdea>Each call that hasn't finished owns one frame on the stack, newest on top. Returning pops it.</KeyIdea>

## Frames in real C

```c
#include <stdio.h>

int square(int n) {
    int result = n * n;
    return result;
}

int sum_of_squares(int a, int b) {
    return square(a) + square(b);
}

int main(void) {
    printf("%d\n", sum_of_squares(3, 4));
    return 0;
}
```

This prints 25. While the first `square(3)` runs, three frames are on the stack, newest on top:

<TruthTable caption='The stack during square(3)' rowsJson='[["frame", "holds"], ["square (top)", "return address into sum_of_squares; n = 3; result"], ["sum_of_squares", "return address into main; a = 3, b = 4; room for the first result"], ["main (bottom)", "return address into the startup code"]]' />

When square returns, its frame is popped; the second call to square then gets a fresh frame in the same place. Which values actually go in memory and which stay in registers is the compiler's choice: you'll see real compiler output, with and without optimisation, in the toolchain section of this course.
