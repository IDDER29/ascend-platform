In the last course you wrote programs one instruction at a time. That works, but it's slow and error-prone, and it ties every program to one CPU. This course climbs one layer up: you write what you want in a programming language, and a <b>translator</b> turns it into instructions.

By the end you'll be able to tell an algorithm from a program, read the small language this course uses, and say what a translator does.

## One procedure, three ways

An <b>algorithm</b> is an exact procedure. Here's one, in English: to add up the numbers from 1 to n, start a total at 0; while n isn't 0, add n to the total and take 1 from n; then show the total.

A <b>program</b> is an algorithm written in a particular <b>programming language</b>. This course uses a deliberately tiny language, built for the tiny CPU. The same algorithm in it:

```
var n = 4;
var total = 0;
while (n != 0) {
  total = total + n;
  n = n - 1;
}
output(total);
```

And in C, the language you'll meet properly in the Systems Programmer path, it would look much the same, with `while (n != 0)` and `total = total + n;`. One algorithm; many languages; and underneath, always instructions.

<KeyIdea>The algorithm is the idea. A program is that idea written in one language. The CPU only ever runs instructions.</KeyIdea>

## What a translator does

A <b>translator</b> (for a real language, a <b>compiler</b>) reads a program and writes the instructions that do the same thing. The lab below shows both sides: your program on the left, the tiny CPU assembly it becomes on the right, with the source line each instruction came from.

The program is missing its most important line. Add the line that adds n to the total, so it outputs 10.

Look at the right-hand side: that one line became four instructions (load total, load n, add, store total). Seven lines of source became 19 instructions.

## Why languages exist

If the CPU only runs instructions, why have languages at all?

- <b>People:</b> `total = total + n` says what you mean; four instructions say how. Programs are read far more often than they're written.
- <b>Portability:</b> assembly belongs to one CPU. The same C program can be compiled for x86 laptops, ARM phones or the tiny CPU (with the right compiler).
- <b>Safety:</b> a language can refuse nonsense before it runs. Try typing `x = y * 2;` in the lab: the translator stops with an error instead of producing a broken program.

The price is that you can no longer see exactly what the CPU does. The rest of this course is about seeing it anyway.
