The word "memory" gets used for two different things. The RAM in a computer and the SSD in it both remember bytes, but they're built differently, used differently, and behave very differently when the power goes.

By the end you'll be able to say which is which, why one forgets, and why saving is a step of its own.

## Two kinds of remembering

**Memory** (RAM) holds the programs that are running and the data they're working on. The CPU reads and writes it all the time, so it has to be fast.

**Storage** (an SSD, or an older spinning disk) keeps programs and files for later: the ones that aren't running, and everything you've saved. It's much bigger and much slower.

The numbers are rough, and they change from machine to machine. Here is what one laptop reports (this is a real run; yours will differ):

```
$ free -h
               total        used        free      shared  buff/cache   available
Mem:            14Gi       5.4Gi       3.5Gi       1.2Gi       7.4Gi       9.4Gi
$ df -h /
/dev/nvme0n1p2  233G  146G   76G  66% /
```

About 14 GiB of RAM, and a 233 GB SSD: the storage is about sixteen times bigger. Notice `buff/cache`: 7.4 GiB of RAM is holding copies of files. That will matter in a moment.

## Why RAM forgets

You built memory from flip-flops in *State and memory*. A flip-flop holds its bit only while current flows through it: cut the power and the bit is gone. Registers and the fast memory inside a CPU work this way.

Main memory (DRAM) stores each bit as a tiny charge in a capacitor. The charge leaks away within milliseconds, so the memory chips rewrite (refresh) every row many times a second. With no power there's no refresh, and the bits fade.

Flash storage traps charge inside an insulated layer of each cell, where it stays for years with no power. Spinning disks store bits as magnetised spots, which also need no power. Writing them is slower, which is the price of keeping them.

<KeyIdea>RAM needs power to hold its bits; storage doesn't. Anything only in RAM is lost when the power goes.</KeyIdea>

## Saving is a separate step

When a program changes data, it changes it in memory. Getting it into storage is a separate request to the operating system: "write these bytes to this file". Even then, the OS usually copies the bytes into its own cache in RAM first (that's the `buff/cache` above) and writes them to the SSD shortly afterwards, because that's faster.

So there's a window where the file looks saved but is still only in RAM. A program that must be sure, such as a database or an editor's autosave, asks the OS to write it now, with `sync` or `fsync`.

## Quitting versus crashing

Now everyday behaviour makes sense:

- **Save, then quit**: the data went to storage, so it's there next time.
- **Quit without saving**: the program's memory is handed back to the OS and reused; the changes are gone.
- **Power cut right after saving**: usually fine, but data still waiting in the OS's cache can be lost. That's why some devices warn you not to pull the plug while they're writing.
