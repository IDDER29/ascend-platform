Text is one code for bytes. Pictures, colours, sound and every file format are others. Nothing about the bytes changes from one to the next; only the agreement about how to read them does.

By the end you'll be able to describe a picture and a sound as numbers, work out how big they are, and say how a program knows what kind of file it has opened.

## Pictures are grids of numbers

A digital picture is a grid of tiny squares called <b>pixels</b>. Each pixel is one colour, and a colour on a screen is a mix of red, green and blue light. The most common code gives each of the three one byte, from 0 (none) to 255 (full).

<TruthTable caption='Colours as three bytes' rowsJson='[["colour", "red", "green", "blue", "hex"], ["black", "0", "0", "0", "000000"], ["white", "255", "255", "255", "FFFFFF"], ["red", "255", "0", "0", "FF0000"], ["orange", "255", "165", "0", "FFA500"], ["mid grey", "128", "128", "128", "808080"]]' />

Three bytes of 256 values each make 256 × 256 × 256 = 16,777,216 possible colours. Those hex codes are the same ones web designers write, such as #FFA500.

<ByteLab caption='Three bytes read as a colour' bytesJson='[255, 165, 0]' />

Size follows directly. A 1920 × 1080 picture has 2,073,600 pixels; at 3 bytes each that's 6,220,800 bytes, over 6 MB for one picture. Formats like PNG and JPEG exist to store the same grid in fewer bytes.

## Sound is a list of measurements

Sound is air pressure rising and falling smoothly, an analog signal. To store it, a computer measures the pressure many times a second and writes each measurement down as a number. Each measurement is a <b>sample</b>.

Two numbers describe the recording:

- The <b>sample rate</b>: how many samples per second. A CD uses 44,100.
- The <b>sample size</b>: how many bits per sample. A CD uses 16, so each sample is one of 65,536 values.

A CD stores two channels (left and right), so one second takes 44,100 × 2 bytes × 2 channels = 176,400 bytes, and a minute takes 10,584,000 bytes, about 10.6 MB. Played back fast enough, the steps between samples are too small to hear.

<KeyIdea>A picture is a grid of colour numbers; a sound is a list of pressure numbers. Both are bytes with an agreed way to read them.</KeyIdea>

## Files say what they are in their first bytes

A file is just a long row of bytes. How does a program know whether to read them as a picture, a document or a zip? The name's ending (.png, .pdf) is a hint, but it can be wrong or missing. Most formats start with a fixed <b>signature</b>, sometimes called a magic number:

<TruthTable caption='The first bytes of some formats' rowsJson='[["format", "first bytes (hex)", "as ASCII"], ["PNG image", "89 50 4E 47", "a byte, then PNG"], ["PDF document", "25 50 44 46", "%PDF"], ["GIF image", "47 49 46 38", "GIF8"], ["ZIP archive", "50 4B", "PK"]]' />

After the signature comes a <b>header</b>: the agreed facts a reader needs before the data, such as an image's width and height. Then comes the data itself. A file format is a codebook written down precisely enough that programs by different people can all read it.

<KeyIdea>A file's format is an agreement about its bytes. The signature at the start says which agreement to use.</KeyIdea>
