You've stored values in separate variables, one box each. When you have many values of the same kind (scores, pixels, letters of a name) you want them together, so a loop can walk through them. That's an <b>array</b>.

By the end you'll be able to say where any element lives and walk through an array on the tiny CPU.

## Neighbouring boxes

An array is values of one type stored side by side in memory. On the tiny CPU, an array of 5 bytes at 0x90 takes boxes 0x90, 0x91, 0x92, 0x93 and 0x94. Element 0 is at 0x90; element 4 is at 0x94.

## Where element i lives

When elements are bigger than a byte, they're further apart. This C program prints how far each element of an int array is from the first:

```c
#include <stdio.h>

int main(void) {
    int a[4] = {10, 20, 30, 40};
    char *start = (char *)&a[0];
    for (int i = 0; i < 4; i++) {
        printf("a[%d] = %d, %ld bytes from the start\n", i, a[i], (long)((char *)&a[i] - start));
    }
    return 0;
}
```

```
a[0] = 10, 0 bytes from the start
a[1] = 20, 4 bytes from the start
a[2] = 30, 8 bytes from the start
a[3] = 40, 12 bytes from the start
```

Each int is 4 bytes, so element i is 4 × i bytes along. That's the whole rule:

<KeyIdea>Element i lives at the start address plus i times the element's size. Indexing an array is one multiply and one add.</KeyIdea>

It's also why counting starts at 0: element 0 is 0 elements along from the start.

## Walk through an array

To visit every element, keep the address of the current one in a register and add the size after each step. This program should add up the five bytes at 0x90 and output 35. It outputs 15. Find the missing line.

Add `INC R1` after `ADD R0, R3`. Without it, R1 stays at 0x90 and the loop reads element 0 (the 3) five times: 15. With it, R1 walks 0x90, 0x91, ... 0x94 and the total is 3 + 5 + 7 + 9 + 11 = 35. R1 is doing exactly what an array index does in a language.

## Past the end

Nothing in memory marks where an array stops. If the loop above ran six times, it would read box 0x95 too, whatever happened to be there, and add it in. In C, reading or writing past the end of an array is undefined behaviour: it may read another variable, crash, or appear to work. Keeping the index inside the array is the program's job, which is why the Systems Programmer path spends a whole course on C's rules.
