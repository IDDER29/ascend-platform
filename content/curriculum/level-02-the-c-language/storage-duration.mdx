Scope, from C Basics, answers *where a name can be used*. **Storage duration** answers a different question: *how long the object itself exists*. They often line up, but not always: a `static` local has a small scope and lives for the whole run. C has three durations you'll use every day.

| Duration | How you get one | Created | Destroyed |
|---|---|---|---|
| automatic | a local variable, a parameter | each time its block starts | when its block ends |
| static | a global, or `static` anywhere | once, before `main` | when the program ends |
| allocated | `malloc`, `calloc`, `realloc` | when the call returns | when you call `free` |

## All three in one program

<CRun program="c-language/sd-lifetimes" caption='Three lifetimes' />

`count` is static, so the three calls share one object, and the third call sees 3. Inside `make_array`, `a` and `i` are automatic and vanish when it returns, but the block `malloc` gave it is allocated: it outlives the function, so `main` can still read `squares[4]`, until `free` ends it.

<KeyIdea>Automatic objects die with their block, static ones live for the whole run, and allocated ones live until you free them. A pointer is only valid while the object it points at still exists.</KeyIdea>

## The dangling pointer

What could go wrong here? Read gcc's message, then predict what running it does.

<CRun program="c-language/sd-dangling" caption='Returning the address of a local' predict />

<details>
<summary>Check your answer</summary>

gcc warns, `function returns address of local variable`, and running it crashes with a segmentation fault. `answer` is automatic: it stops existing the moment `make_answer` returns, so the pointer it hands back points at nothing valid. Using it is undefined behaviour.

This gcc goes further than warning. Because the code can never be correct, it returns a null pointer instead of the dead address (look at its `-S` output: `movl $0, %eax`), so the bug crashes at once instead of quietly printing 42. Other compilers, or other flags, may print 42, print garbage, or crash later: none of those means the code is fine.

</details>

The warning only catches the obvious case. Store the address somewhere instead of returning it, and gcc says nothing. AddressSanitizer catches it at run time:

<CRun program="c-language/sd-dangling-asan" caption='The same bug, hidden from the warning' />

The report names the bug, **stack-use-after-return**, says the bad read happened in `main`, and names the variable the memory belonged to: `'answer' (line 6)` in `make_answer`'s frame. (Compile with `-g` too, and ASan adds the exact line of every frame.) The addresses change from run to run; the diagnosis doesn't.

The fixes: return the value itself (`int make_answer(void)`), let the caller pass in where to put the result, or return allocated memory and make the caller responsible for freeing it.

## What they start as

Predict all five values this prints:

<CRun program="c-language/sd-static-init" caption='Static objects with no initialiser' predict />

<details>
<summary>Check your answer</summary>

`0 0 0 0.000000 NULL`. Every object with static storage duration (globals, file-scope `static`, and `static` locals) is initialised before `main` runs, and if you don't give a value, C sets it to zero: 0 for numbers, 0.0 for `double`, a null pointer for pointers, and every element of an array.

Automatic objects get no such guarantee. A local `int x;` holds whatever bytes were left on the stack, and reading it before assigning is undefined behaviour. That's why gcc's `-Wall` warns about "may be used uninitialized". Always initialise locals.

</details>

## Static means set up before main

A static object is initialised once, before any of your code runs. So what's wrong with this?

<CRun program="c-language/sd-not-constant" caption='Initialising a static from a function' />

<details>
<summary>Check your answer</summary>

`initializer element is not constant`. Static objects are filled in when the program is loaded, before `main` and before any function can run, so their initial value must be something the compiler can work out: a constant expression such as `10`, `3 * 4` or the address of another static object. A function call isn't. Set it at the start of `main` instead: `counter = start();`.

</details>
