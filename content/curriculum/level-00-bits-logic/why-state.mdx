You've seen two things that don't fit together yet. Gates compute: their outputs depend only on their inputs right now. Machines like the turnstile remember: what they do depends on what happened before. This lesson joins them into one pattern, and it's the pattern every part of a computer that changes over time is built on.

By the end you'll be able to describe any stateful machine as a state and a rule, point at the part of a circuit that holds the state, and trace it tick by tick.

## State plus a rule

Describe a machine with state in two parts:

- its <b>state</b>: what it remembers right now;
- its <b>next-state function</b>: a rule that takes the current state and the inputs, and gives the state it should have next.

The turnstile's rule was its table: locked plus a coin gives unlocked, unlocked plus a push gives locked. That rule is a truth table, so it can be built from gates. The state can't be built from gates alone; it needs somewhere to be kept: a <b>register</b>, a row of memory cells called flip-flops. The next two lessons build both; here we only need what a register does.

So a stateful circuit has exactly two pieces, connected in a loop:

<TruthTable caption='The two pieces of every stateful circuit' rowsJson='[["piece", "what it is", "what it does"], ["register", "flip-flops", "holds the current state"], ["next-state logic", "combinational gates", "works out the next state from the state and the inputs"]]' />

The register's output feeds the logic. The logic's output feeds back into the register. Around and around.

<KeyIdea>Every stateful circuit is a register holding the state, and gates working out what it should become next.</KeyIdea>

## The tick decides when

A loop from the logic back into the register sounds as if it would spin out of control. It doesn't, because of the <b>clock</b>, a signal that ticks at a steady rate (you'll meet it properly two lessons from now). The register only takes in its input at a <b>tick</b>. Between ticks, the logic in front of it can work things out and settle, and the stored state stays exactly where it was.

That answers a common worry: a clocked register does not change whenever its input changes. Its input can flicker for most of the cycle; only the value present at the tick is captured. Feedback through a register is controlled feedback: one step per tick.

So a machine runs like this, over and over:

1. The register shows the current state.
2. The logic works out the next state from it and from the inputs.
3. The clock ticks, and the register takes in the next state.

## A circuit that remembers a press

Here is the doorbell problem again, made smaller: one button, P, and one bit of state, PRESSED, which should become 1 the first time the button is pressed and stay 1 for good.

In the lab below, each line with `:=` gives a register's value after the next tick. The starting line just copies the button, so it forgets the press as soon as the button is released. Fix it so it remembers. Hint: the next state can use the current state.

`PRESSED := PRESSED OR P`. Once PRESSED is 1, PRESSED OR P is 1 whatever the button does, so the register keeps it. The old state flowing back into the logic is what turns forgetting into remembering.

<KeyIdea>State feeding back into its own next-state logic is how a circuit remembers. The clock makes it happen one step at a time.</KeyIdea>

The rest of this course builds on that loop: counters, which add 1 to their state at each tick; state machines, which follow steps; and memory, which is many registers with addresses.
