Sometimes a program needs the same few instructions in several places: double a number, add up a list, show a value. Copying them each time wastes memory and invites mistakes. A <b>subroutine</b> is one copy that every part of the program can use, as long as it can find its way back afterwards.

By the end you'll be able to call a subroutine, trace how it returns, and write one that doesn't disturb the registers of the code that called it.

## Jumping and coming back

A JMP can get you to the subroutine, but not back: the subroutine doesn't know where it was called from, and it's called from more than one place. It needs a <b>return address</b>, the address of the instruction just after the call. And the place to keep it is the stack.

## CALL and RET

- <b>CALL label</b> pushes the return address (its own address + 2) onto the stack, then jumps to the label.
- <b>RET</b> pops the return address off the stack into the program counter.

This program calls the subroutine `double` from two places:

<TinyCpu2 caption='One subroutine, called twice' programJson='["LDI R0, 5", "CALL double", "OUT R0", "LDI R0, 21", "CALL double", "OUT R0", "HALT", "double: ADD R0, R0", "RET"]' />

It shows 10, then 42. The first CALL is at 0x02, so it pushes 0x04; the second is at 0x08 and pushes 0x0A. Each time, RET pops the right address, and the program carries on just after the call that was made.

<KeyIdea>CALL = push the return address, then jump. RET = pop it back into the program counter.</KeyIdea>

## Calls inside calls

A subroutine can call another. Each CALL pushes one more return address, and each RET pops the newest, so they unwind in the right order:

<TinyCpu2 caption='A call inside a call' programJson='["CALL a", "HALT", "a: LDI R0, 1", "OUT R0", "CALL b", "OUT R0", "RET", "b: LDI R0, 2", "OUT R0", "RET"]' />

It shows 1, 2, 2. Inside b the stack holds two return addresses: one back into a, and one back into the main program. Last in, first out is exactly the order calls finish in.

## Saving the registers you use

This program keeps 100 in R1, then calls `triple`, which uses R1 for its own working. Step through it:

<TinyCpu2 caption='A subroutine that clobbers R1' programJson='["LDI R1, 100", "LDI R0, 2", "CALL triple", "ADD R0, R1", "OUT R0", "HALT", "triple: MOV R1, R0", "ADD R0, R1", "ADD R0, R1", "RET"]' />

It shows 8, not 106: triple left 2 in R1, so the main program's 100 was lost. The fix is for triple to save R1 on the stack first and restore it before returning:

<TinyCpu2 caption='Saving R1 on the stack' programJson='["LDI R1, 100", "LDI R0, 2", "CALL triple", "ADD R0, R1", "OUT R0", "HALT", "triple: PUSH R1", "MOV R1, R0", "ADD R0, R1", "ADD R0, R1", "POP R1", "RET"]' />

Now it shows 106. Push and pop must pair up exactly inside the subroutine: if they didn't, RET would pop the wrong value as its return address.

<KeyIdea>A good subroutine gives back every register it doesn't return a result in. PUSH at the start, POP before RET.</KeyIdea>
