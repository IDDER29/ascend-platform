The fetch-execute loop fetches instructions and does them. But which instructions? A CPU only understands a fixed list, each with its own bit pattern. That list is its <b>instruction set</b>, and it's the vocabulary every program for that CPU is written in.

By the end you'll be able to read an instruction byte, follow a short program for a tiny CPU address by address, and explain why programs live in memory alongside their data.

## What a CPU can be told to do

An <b>instruction set architecture</b> (ISA) is the contract between hardware and software: the list of instructions, what each one does, and how each is encoded in bits. Programmers and compilers write to the contract; chip designers build circuits that honour it.

That split matters. Intel and AMD build very different circuits, yet both run the same x86-64 instructions, so the same programs run on both. The ISA says <i>what</i> each instruction does; the circuits underneath decide <i>how</i>.

Real instruction sets have hundreds of instructions, but they're the same kinds: move data, do arithmetic, compare, jump.

## An instruction is a byte

Each instruction fits in one byte. The top four bits are the <b>opcode</b>, which says which instruction it is. The bottom four are the <b>operand</b>, which says what to do it to: usually an address.

So 0001 1110 splits into 0001 (LDA) and 1110 (14): load the byte at address 14 into A. And 0010 1111 is ADD 15. The CPU's decode step is exactly this split, done by gates.

## Code and data share memory

Look at address 14 again: 0001 1100. Read as data it's the number 28. Read as an instruction it would be LDA 12. The box doesn't know; only the program counter decides. If the CPU ever fetched from address 14, it would run the number as an instruction.

This is the <b>stored-program</b> idea, usually credited to John von Neumann: programs are bits in the same memory as data, so changing the program means changing memory, not rewiring the machine. (Some designs, called Harvard architectures, keep the two in separate memories.) It's what makes a general-purpose computer, and it's also why a bug that lets data be run as code is so dangerous.

<KeyIdea>A program is just bytes in memory. Whether a byte is an instruction or a number depends only on how the CPU reaches it.</KeyIdea>
