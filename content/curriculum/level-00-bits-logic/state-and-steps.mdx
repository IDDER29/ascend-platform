Press a button on a calculator and you know what you'll get. Press the button on a lift and what happens depends on where the lift already is. The difference is that the lift remembers something. That memory is called state, and every computer has it.

By the end you'll be able to say what a machine's state is, explain why the same input can do different things, and trace a machine one step at a time.

## What state means

A machine's <b>state</b> is everything it remembers that affects what it does next. A light switch has two states, on and off. A lift's state includes which floor it is on and which way it is going. A computer's state is everything in its memory.

An <b>input</b> is something that happens to the machine: a button press, a coin, a key. Each input moves the machine from its current state to a next state, and may produce an <b>output</b>.

## Same input, different result

It is tempting to think a machine always does the same thing for the same input. That is only true for machines without state. With state, the result depends on two things: the input, and the state it arrives in.

<KeyIdea>Result = input + current state. The same input can do different things because the state is different.</KeyIdea>

A coin-operated turnstile shows this. It has two states, locked and unlocked, and two inputs, a coin and a push:

<TruthTable caption='The turnstile: next state for each state and input' rowsJson='[["state now", "input", "next state", "what happens"], ["locked", "coin", "unlocked", "it lets you through on the next push"], ["locked", "push", "locked", "nothing, it stays shut"], ["unlocked", "push", "locked", "you go through, it locks behind you"], ["unlocked", "coin", "unlocked", "nothing new, it is already open"]]' />

A push does nothing to a locked turnstile and lets you through an unlocked one. Same input, different state, different result.

## A turnstile, step by step

To trace a machine, write its state before and after every input, one row per step:

<TruthTable caption='Tracing five inputs' rowsJson='[["step", "state before", "input", "state after"], ["1", "locked", "push", "locked"], ["2", "locked", "coin", "unlocked"], ["3", "unlocked", "push", "locked"], ["4", "locked", "coin", "unlocked"], ["5", "unlocked", "coin", "unlocked"]]' />

Each row starts from the state the row before ended in. That chain is what makes the trace honest: you can't jump to the end without going through every step.

## Time: one step at a time

A machine with state works in steps. Between steps its state stays the same; at each step it changes once. Most things stay the same in any one step. In step 3 only the lock changed; the turnstile, its coin box and its location did not.

When a machine misbehaves, look for the <b>first</b> step where the state after differs from what you expected. Everything after that step is just a consequence.

<KeyIdea>To understand a machine with state, trace it: state before, input, state after, one step at a time.</KeyIdea>

Computers are built exactly this way. Later in this path you'll see circuits that hold state, a clock that decides when each step happens, and a CPU whose every instruction is one step from one state to the next.
