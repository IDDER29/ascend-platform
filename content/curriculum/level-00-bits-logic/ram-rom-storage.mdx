You've built two places to keep bits: a register (a few flip-flops in a row) and memory (thousands of registers with addresses). A real computer has more than these, and they don't all do the same job. Some forget everything when the power goes off; some keep it for years.

By the end you'll be able to name four places a computer keeps bits, say what each one is for, and explain why a computer needs both memory and storage.

## Four places for bits

<TruthTable caption='Where bits live' rowsJson='[["place", "what it holds", "roughly how much", "power off"], ["registers", "the values the CPU is working on this instant", "a few to a few dozen", "lost"], ["RAM", "running programs and their data", "billions of bytes", "lost"], ["ROM or flash firmware", "the first program that runs at power on", "thousands to millions of bytes", "kept"], ["storage (SSD or disk)", "files, apps and the operating system", "hundreds of billions of bytes and more", "kept"]]' />

- <b>Registers</b> are inside the CPU itself. There are only a handful, and the CPU can use them on every clock tick. The tiny CPU in this path has register A and register B.
- <b>RAM</b> (random-access memory) is the row of numbered boxes from the last lesson. "Random access" means any box can be reached by its address, as quickly as any other.
- <b>ROM</b> (read-only memory) holds bits that are set when the chip is made, or, in modern machines, <b>flash</b> that can be rewritten but rarely is. It holds <b>firmware</b>: the small program that runs first when the computer switches on.
- <b>Storage</b> is an SSD or a hard disk. It holds everything you save, and it is far larger than RAM.

## Forgetting and keeping

The biggest difference is what happens when the power goes off.

Registers and RAM are <b>volatile</b>: they need power to keep their bits. A latch holds a bit only because its feedback loop is powered. RAM in a real computer is even more fragile: each bit is a tiny charge that leaks away, so the chip rewrites every bit many times a second just to keep it. Cut the power, and everything in them is gone.

ROM, flash and disks are <b>non-volatile</b>. Flash traps charge in cells that hold it for years without power; a hard disk stores bits as magnetised spots. Switch off, switch on, and the bits are still there.

<KeyIdea>Volatile memory forgets when the power goes off. Non-volatile memory keeps its bits. That one difference decides what each kind is used for.</KeyIdea>

## Why not one kind of memory?

A common belief is that RAM and storage do the same job: both "store things". They don't, and the reason is a trade-off.

- Storage is <b>slow to reach</b>. Even a fast SSD takes roughly hundreds to thousands of times longer to answer than RAM does, and a hard disk, which has to move a head over a spinning platter, roughly a hundred times longer again. A CPU working straight from storage would spend nearly all its time waiting.
- RAM is <b>fast but forgetful</b>, and it costs much more per byte, which is why a computer has many times more storage than RAM.

So they work as a pair. When you open an app, its code and data are copied from storage into RAM, and the CPU works on that copy. When you save, the changes are written back to storage. Anything you haven't saved exists only in RAM, which is why a power cut loses it.

<KeyIdea>RAM is where a program works. Storage is where it is kept. Opening copies from storage to RAM; saving copies back.</KeyIdea>

## Where a running program lives

Put together, a program you are using right now is spread over all four places:

- its <b>code and data</b> are copied into RAM from storage when it starts;
- the <b>values it is computing with this instant</b> sit in registers;
- the <b>firmware</b> that started the computer is in ROM or flash;
- its <b>saved files</b>, and the program itself, are kept in storage for next time.

The Complete System course comes back to this, with the ladder of faster and smaller memories between the CPU and storage. For now, the rule to keep is simple: registers and RAM are fast and forget; ROM and storage are slow to change and remember.
