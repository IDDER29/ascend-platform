You can now read and write numbers in binary. Real computers never handle a loose, open-ended row of bits, though. They work in fixed sizes: so many bits, no more, no fewer. This lesson names those sizes and shows what each one can hold.

By the end you'll be able to say how many values fit in a given number of bits, name the common sizes, and explain why a 500 GB drive shows up as 465.

## Every bit doubles the patterns

One bit has 2 patterns: 0 and 1. Add a second bit and each of those can be followed by a 0 or a 1, so there are 4: 00, 01, 10, 11. Every extra bit doubles the count again.

<TruthTable caption='How much fits in n bits' rowsJson='[["bits", "patterns", "unsigned range"], ["1", "2", "0 to 1"], ["4", "16", "0 to 15"], ["8", "256", "0 to 255"], ["16", "65,536", "0 to 65,535"], ["32", "4,294,967,296", "0 to 4,294,967,295"]]' />

The largest number is always one less than the number of patterns, because counting starts at 0. That is why 255 turns up so often: it is the biggest value one byte can hold.

<KeyIdea>n bits make 2 to the power n patterns. Counting from 0, the largest unsigned value is that number minus one.</KeyIdea>

## Nibbles and bytes

Some sizes have names:

- A <b>nibble</b> is 4 bits. It holds 0 to 15, which is exactly one hexadecimal digit. That is why hex is so convenient: two hex digits are one byte.
- A <b>byte</b> is 8 bits, the smallest amount most computers give an address to. A memory address names a byte, not a bit. A byte holds 0 to 255, or 00 to FF in hex.

<ByteLab bytesJson='[255, 15, 170]' caption='Three bytes: click any bit to flip it' />

Early computers used bytes of different sizes. The 8-bit byte became the standard in the 1960s, with IBM's System/360. It is a power of two, splits neatly into two nibbles, and has room for every letter, digit and punctuation mark in English text.

## Words: the size a CPU likes

A <b>word</b> is the amount of data a particular CPU handles most naturally: the width of its registers and of most of its arithmetic. Unlike a byte, a word is not one fixed size.

<TruthTable caption='Word sizes on different machines' rowsJson='[["machine", "word"], ["the tiny CPU in this path", "8 bits"], ["many 1980s home computers", "8 or 16 bits"], ["PCs in the 1990s and 2000s", "32 bits"], ["most laptops and phones today", "64 bits"]]' />

When someone says a computer is "64-bit", they mean its word is 64 bits wide: it adds, compares and moves 64-bit numbers in one step. A wider word handles bigger numbers at once and can name more memory addresses.

<KeyIdea>A byte is always 8 bits. A word is whatever size the CPU in front of you works in.</KeyIdea>

## Kilobytes and kibibytes

In everyday units, kilo means 1000. But 1000 isn't a power of two, and 1024 (2 to the power 10) is close to it, so early programmers borrowed "kilobyte" for 1024 bytes. Now the same word means two different numbers, and the gap grows with every step up:

<TruthTable caption='Two ways to count' rowsJson='[["name", "powers of 1000", "powers of 1024"], ["kilo / kibi", "1,000", "1,024"], ["mega / mebi", "1,000,000", "1,048,576"], ["giga / gibi", "1,000,000,000", "1,073,741,824"]]' />

The standard fix is a separate name for the binary units: <b>kibibyte</b> (KiB) for 1024 bytes, mebibyte (MiB), gibibyte (GiB). Drive makers count in powers of 1000. Many operating systems count in powers of 1024 but still print "GB". So a drive sold as 500 GB, which is 500,000,000,000 bytes, shows up as about 465 "GB": 500,000,000,000 divided by 1,073,741,824. No bytes are missing; the units are different.

That's the size of things. Next you'll add numbers that have to fit in one of these fixed sizes, and see what happens when they don't.
