An <b>expression</b> is anything that works out to a value: `a + 1`, `total - n`, `10 - 3 + 1`. The CPU can only do one operation at a time, on two values, so every expression becomes a sequence of single steps. The language has to say what order they go in.

By the end you'll be able to work out an expression step by step and know why the order matters.

## One step at a time

The tiny language works out `+` and `-` strictly from left to right:

<TruthTable caption='10 - 3 + 1, step by step' rowsJson='[["step", "what happens", "running value"], ["1", "start with 10", "10"], ["2", "take away 3", "7"], ["3", "add 1", "8"]]' />

So `10 - 3 + 1` is 8. If you did the `+` first, `10 - (3 + 1)` would be 6. Same symbols, different order, different answer.

The translator does exactly these steps in one register: load the first value into R0, then for each `+` or `-`, load the next value into R1 and add or subtract it. In the lab, the line `output(a - 5 + 5);` becomes LDA, LDI, SUB, LDI, ADD, OUT.

<KeyIdea>An expression is a recipe of single steps. The language decides their order; the CPU just follows it.</KeyIdea>

## Precedence in real languages

Real languages have more operators, so they need more rules. In C, `*` and `/` are done before `+` and `-`; this is called <b>precedence</b>. Brackets override it:

```c
#include <stdio.h>

int main(void) {
    printf("%d\n", 2 + 3 * 4);
    printf("%d\n", (2 + 3) * 4);
    printf("%d\n", 10 - 3 - 2);
    return 0;
}
```

This prints:

```
14
20
5
```

The last line shows the left-to-right rule again: `10 - 3 - 2` is `(10 - 3) - 2`, which is 5, not `10 - (3 - 2)`, which would be 9.

One more thing C does that the tiny language doesn't: when both sides of a `+` are function calls, C doesn't promise which call happens first. If the order matters to your program, put the calls on separate lines. You'll meet this again in The C Contract.
