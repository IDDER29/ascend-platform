The tiny CPU, like most modern CPUs, does its work in registers. Memory only takes part through two kinds of instruction: **loads**, which copy a box into a register, and **stores**, which copy a register into a box.

By the end you'll be able to copy and swap boxes, store through a pointer, and explain why a careless store can rewrite the program itself.

## Memory to register and back

There's no instruction that copies one box straight to another. A copy is always two steps: load, then store.

<TruthTable caption='The loads and stores of version 2' rowsJson='[["instruction", "what it does"], ["LDA R0, [0x80]", "R0 = the value in box 0x80"], ["STA R0, [0x81]", "box 0x81 = R0"], ["LDR R0, [R1]", "R0 = the value in the box R1 points at"], ["STR R0, [R1]", "the box R1 points at = R0"]]' />

None of these change the Z flag. Moving a value isn't a calculation, so it leaves the flags as they were.

## Swapping two boxes

Boxes 0x80 and 0x81 hold 3 and 9. Swap them, so 0x80 holds 9 and 0x81 holds 3. The starting program is a common first try, and it doesn't work: run it and look at the two boxes in the memory grid.

<TinyCpu2 editable caption='Swap boxes 0x80 and 0x81' programJson='["LDA R0, [128]","STA R0, [129]","HALT"]' dataJson='{"128":3,"129":9}' goalJson='{"mem":{"128":9,"129":3}}' />

<details>
<summary>Check your answer</summary>

The starting program copies the 3 over the 9, and the 9 is gone for good. Load both values first, then store them crosswise:

- `LDA R0, [128]`
- `LDA R1, [129]`
- `STA R0, [129]`
- `STA R1, [128]`
- `HALT`

On version 1, with one register, you'd need a spare box to hold one value. Four registers make it easier.

</details>

<KeyIdea>A store overwrites. Before you write to a box, make sure its old value is either safe in a register or no longer needed.</KeyIdea>

## Storing through a pointer

STR is the store version of LDR: the address comes from a register. This program puts 0x90 in R1 and 7 in R0, then stores R0 into the box R1 points at.

<TinyCpu2 caption='Store through a pointer' programJson='["LDI R1, 0x90","LDI R0, 7","STR R0, [R1]","HALT"]' />

Box 0x90 becomes 7. Change R1 and the same STR writes a different box: that's how a loop fills a whole list.

## Nothing guards the code

Code and data share one memory, and version 2 doesn't protect the code area: a store can write any box, including one that holds an instruction. This program stores 0xA8, the first byte of HALT, into box 0x06, which holds the start of a NOP. Predict what it shows before you run it.

<TinyCpu2 caption='A store that rewrites the program' programJson='["LDI R0, 0xA8","STA R0, [0x06]","LDI R1, 0","NOP","LDI R0, 9","OUT R0","HALT"]' />

It shows nothing. When the program counter reaches 0x06, the CPU fetches HALT and stops before the OUT. Real computers protect their code from this kind of accident; you'll see how in The Complete System.

<KeyIdea>Memory is just numbered boxes. Code, data and the stack are a convention about which boxes hold what, and on this CPU, nothing enforces it.</KeyIdea>
