You've seen that a bit is the answer to one yes/no question. One bit can't say much. Put a few side by side and you can say a lot more, but only once everyone agrees what each pattern stands for.

By the end you'll be able to explain what a code is, work out how many messages a code can carry, and say why the same bits can mean completely different things.

## A code is an agreement

A <b>code</b> is an agreed list that pairs each pattern of bits with a meaning. Here is one for a tiny doorbell display, using two bits:

<TruthTable caption='A 2-bit doorbell code' rowsJson='[["pattern", "meaning"], ["00", "nobody there"], ["01", "delivery"], ["10", "visitor"], ["11", "emergency"]]' />

Nothing about 10 means "visitor". Someone decided it, wrote it down, and both the doorbell and the display were built to follow that decision. If the display had been built from a different table, the same 10 might light up "delivery".

<KeyIdea>A code is a shared agreement. The sender encodes with it, the receiver decodes with it, and both must use the same one.</KeyIdea>

## How many messages fit

Each bit you add doubles the number of patterns, because every old pattern can now end in a 0 or a 1:

<TruthTable caption='More bits, more patterns' rowsJson='[["bits", "patterns", "examples"], ["1", "2", "0, 1"], ["2", "4", "00, 01, 10, 11"], ["3", "8", "000 up to 111"], ["8", "256", "00000000 up to 11111111"]]' />

So n bits give 2 to the power n different patterns. If you need to tell apart 5 messages, 2 bits (4 patterns) aren't enough and 3 bits (8 patterns) are, with 3 patterns left over.

## One pattern, many meanings

Take the eight bits 01000001. What do they mean?

- Read as a whole number in binary, they are 65.
- Read with <b>ASCII</b>, the standard code for text, they are the capital letter A.
- Read with a code of your own, they could be "turn left" or a shade of grey.

The bits are identical every time. Only the code changed. A computer's memory is full of patterns like this, and nothing in memory says which code they were written with. The program reading them has to know.

<KeyIdea>Meaning is not stored in the bits. It comes from the code used to read them.</KeyIdea>

## When codes don't match

A message can arrive with every bit perfect and still be wrong. If you send 10 meaning "visitor" and the display decodes with a table where 10 means "delivery", nothing was lost in transit. The two sides simply didn't share a code.

This is why so much of computing is about agreeing on codes: text standards like ASCII, file formats, network protocols. Each one is a carefully written agreement so that bits written by one machine mean the same thing when another machine reads them.
