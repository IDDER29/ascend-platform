After pass one, the assembler knows every instruction's address and every label's value. <b>Pass two</b> walks the program again and writes each instruction as its two bytes.

By the end you'll be able to encode any tiny CPU instruction by hand, and check your bytes against the real assembler.

## Two bytes per instruction

Every instruction is two bytes. The first byte always has the same layout; the second depends on the kind of instruction:

## The first byte: opcode and register

Take ADD R0, R1. ADD's opcode is 5, which is 00101 in five bits. The destination register Rd is R0, which is 00. The last bit is 0. Put together: 00101 00 0, which is 0010 1000, or 0x28.

A different register changes only bits 2 and 1. R1 is 01, so it adds 0x02; R2 adds 0x04; R3 adds 0x06. LDA R1, [0x80] starts with 0x10 + 0x02 = 0x12.

<KeyIdea>First byte = opcode × 8 + register × 2. The opcode sits in the top five bits, the register just below it.</KeyIdea>

## The second byte depends on the format

<TruthTable caption='The second byte' rowsJson='[["format", "examples", "second byte"], ["register", "ADD R0, R1 and MOV R3, R0", "Rs in the top 2 bits, the rest 0"], ["immediate", "LDI R0, 7", "the number itself"], ["address", "LDA R1, [0x80]", "the address"], ["jump", "JNZ loop", "the target address, from the label table"], ["one register", "OUT R0 and DEC R0", "0"], ["none", "HALT and RET", "0"]]' />

So ADD R0, R1 is 28 40: R1 is 01, in the top two bits, 0100 0000. LDA R1, [0x80] is 12 80. And JNZ loop, with loop = 0x04, is 78 04.

The bits marked 0 are <b>reserved</b>: they must be 0. If one isn't, the CPU refuses to run the instruction, so a corrupted byte is caught at once instead of doing something strange.

## Encode a program

The addresses are given. Write each instruction's two bytes, in hex:

<details>
<summary>Check your answer</summary>

08 07, 12 80, 28 40, 18 81, A8 00. If box 0x80 holds 5, this program leaves 12 in box 0x81.

</details>

Now do both passes, on a program with a label used before it's defined:

<AssemblerLab caption='Both passes' programJson='["LDI R0, 3", "loop: OUT R0", "DEC R0", "JZ done", "JMP loop", "done: HALT"]' passJson='both' />

<details>
<summary>Check your answer</summary>

Pass one: 0x00 to 0x0A in steps of 2, with loop = 0x02 and done = 0x0A. Pass two: 08 03, 80 00, B8 00, 70 0A, 68 02, A8 00. JZ is opcode 14, so it starts 0x70; its target, done, comes from the label table.

</details>

<KeyIdea>Pass two is a lookup and a few shifts: the opcode, the registers, and the label table give every byte.</KeyIdea>
