A CPU can only do arithmetic on what's in its registers, but programs keep their data in memory. Two kinds of instruction move data between them: <b>loads</b> bring a byte from memory into a register, and <b>stores</b> write a register's byte into memory.

By the end you'll be able to run every load and store by its signals, keep addresses and values apart, and explain why a store can even change the program itself.

## Loads read a box

LDA n loads the byte at address n into A. After the fetch:

Box n is only read: it keeps its value. LDA doesn't touch the flags either, because FI isn't on.

LDI n is a shorter load. Its operand is the value itself, so there's nothing to look up:

## An address is not a value

Box 9 holds 42. Then:

- LDA 9 puts <b>42</b> in A: the value stored at address 9.
- LDI 9 puts <b>9</b> in A: the operand itself.

That difference is the most important thing in this lesson. An address says where to look; the value is what you find there. In LDA 9, the 9 is never put in A. It goes to the memory address register, picks a box, and the box's contents go to A.

<KeyIdea>An address picks a box; the value is what's inside it. LDA n uses n to find a value; LDI n uses n as the value.</KeyIdea>

## Stores write a box

STA n stores A into box n. It's a load run backwards:

<TruthTable caption='STA n after the fetch' rowsJson='[["step", "signals", "what changes"], ["2", "IO MI", "the memory address register becomes n"], ["3", "AO RI", "box n becomes the value in A"]]' />

A keeps its value: AO only copies it onto the bus. Whatever was in box n before is gone.

Box 13 ends up holding 20, and the display shows 25. STA saved A's value in box 13 so that LDI could reuse A, and ADD 13 brought the saved value back.

## A store can change the program

Code and data share the same 16 boxes, and STA can write any of them. Nothing stops it from writing over an instruction.

In this program, box 15 holds 240, which is 1111 0000: the byte for HLT. Read it carefully before you run it.

<TinyCpu caption='A program that changes itself' programJson='["LDA 15", "STA 3", "LDI 7", "OUT", "HLT"]' dataJson='{"15": 240}' />

Without the first two instructions, it would show 7. With them, it shows nothing. LDA 15 puts 240 in A, and STA 3 writes it into box 3, which held OUT. When the CPU reaches box 3 it fetches HLT and stops. Watch box 3 change in the memory table as STA runs.

<KeyIdea>A store writes whatever box its address names. If that box holds code, the program itself has changed.</KeyIdea>

Programs that write over their own code are called self-modifying, and real systems mostly forbid it, using memory protection you'll meet in The Complete System. On the tiny CPU nothing protects the code, which makes it the clearest place to see why that protection exists.
