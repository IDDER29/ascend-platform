You've built every piece separately: an adder, registers that hold a byte, memory with addresses, a clock. You've also watched the fetch-execute loop run programs. This lesson connects the two. It shows how those parts are wired together and what makes them do the right thing on each clock tick.

By the end you'll be able to point at each part of the tiny CPU, explain how values move between them, and list the steps behind one instruction.

## Two halves of a CPU

A CPU has two halves:

- The <b>datapath</b> holds and moves data. It is made of the parts you already know: registers, memory, the ALU, and the wires between them.
- The <b>control unit</b> decides what the datapath does on each clock tick. It doesn't hold any of your data. It only switches parts on and off.

<KeyIdea>The datapath is where the data goes. The control unit is what tells it where to go.</KeyIdea>

## One bus, shared by everything

The parts don't each have their own wires to every other part. They share a single set of eight wires called the <b>bus</b>. On each clock tick, one part puts its value on the bus and one or more parts load that value from it.

Each part has two switches the control unit can turn on:

- An <b>out</b> signal: put my value on the bus.
- An <b>in</b> signal: load the value on the bus at the next clock tick.

Only one part may have its out signal on at a time. The bus is one set of wires, so two values on it at once would mix into garbage. Turning outs and ins on in the right order is the whole job of the control unit.

<KeyIdea>Moving a value is one clock tick: one part's out signal, another part's in signal.</KeyIdea>

## The control unit is a lookup table

So what is the control unit, physically? It's a circuit with two inputs:

- the opcode, from the top four bits of the instruction register;
- a <b>step counter</b>, which counts 0, 1, 2, 3, 4 with the clock and goes back to 0 when an instruction is done.

From those two inputs it produces every out and in signal. You could build it from gates, but it's easier to write it as a table: for each opcode and step, which signals are on. Ben Eater's breadboard CPU stores exactly that table in a small memory chip. A table of steps like this is called <b>microcode</b>.

<KeyIdea>Opcode plus step number in, control signals out. That is all a control unit is.</KeyIdea>

That finishes the picture. The clock ticks and the step counter moves on. The control unit looks up which part drives the bus and which part loads it. The datapath moves one value. Repeat that for every step of every instruction and the program runs.
