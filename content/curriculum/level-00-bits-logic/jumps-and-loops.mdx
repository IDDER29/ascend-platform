So far every program ran in a straight line: address 0, then 1, then 2, until it hit HLT. Real programs repeat things and make choices. A CPU does both with one simple idea: an instruction that changes where the next instruction comes from.

By the end you'll be able to explain how a jump works, what a flag is, and trace a loop that counts down and stops by itself.

## A jump rewrites the program counter

After each fetch, the program counter normally moves to the next address. A <b>jump</b> instruction overrides that: it loads a new address into the program counter, and the next fetch comes from there.

In our tiny instruction set, JMP n (opcode 0110) does exactly this. A program that ends with JMP 0 starts over forever: that's the simplest loop, and also the simplest way to hang a computer.

<KeyIdea>A jump doesn't do any work itself. It changes the program counter, so the CPU fetches from somewhere else next.</KeyIdea>

## Flags: what happened last time

To decide, the CPU needs to know something about the last result. After every add or subtract, the ALU sets a few one-bit registers called <b>flags</b>. Our tiny CPU has two:

- The <b>zero flag</b> is 1 when the result was exactly 0.
- The <b>carry flag</b> is 1 when the addition carried out of the top bit (in this design subtraction sets it too, to say no borrow was needed).

## Conditional jumps

A <b>conditional jump</b> jumps only when a flag is set, and otherwise lets the program carry straight on. Our CPU has JZ n (opcode 1000, jump if zero) and JC n (opcode 0111, jump if carry).

That's all a CPU needs to choose. An if is "compute something, then jump past the code if the condition isn't met". A loop is "do the body, then jump back to the start unless we're done".

Trace it: A starts at 3 and is shown. SUB makes it 2; the zero flag is 0, so JZ falls through and JMP goes back to show 2. The same happens for 1. The fourth SUB makes A 0, the zero flag is set, and JZ jumps out to address 5, which shows 0 and halts.

## Every if and loop is a jump

High-level languages hide this, but underneath it's always the same. A C `while (n != 0)` becomes a compare and a conditional jump out, plus an unconditional jump back to the top. An `if` becomes a compare and a conditional jump around the code inside it. Even calling a function is a jump, one that remembers where to come back to; you'll meet that in the call stack lesson.

<KeyIdea>Compares set flags; conditional jumps read them. Every decision a program makes is built from those two steps.</KeyIdea>
