This optional project compares two control units for the same tiny CPU.

- **Design 1, stop early:** each instruction takes exactly as many ticks as its steps need. This is the table you wrote.
- **Design 2, fixed length:** every instruction takes 5 ticks; shorter ones wait out the rest with empty ticks. It's simpler to build, since the step counter always counts to 5. Ben Eater's computer started this way.

## Part 1: Same results, different ticks

Predict first: will the fixed design give different answers? Then compare the tick counts for the three programs.

<details>
<summary>Check your answer</summary>

Same answers every time: 42; 3, 2, 1, 0; and 18. The ticks differ: 15 against 18, 48 against 68, and 103 against 128. Design 2 only adds empty ticks, so it can never change what a program does, only how long it takes.

</details>

## Part 2: Ticks per instruction

The countdown runs 14 instructions (count them in its trace, or trust the lab). Work out the average ticks per instruction for each design.

<details>
<summary>Check your answer</summary>

48 ÷ 14 is about 3.4 ticks per instruction for design 1, and 68 ÷ 14 is about 4.9 for design 2. With the same clock speed, design 1 runs this program about 1.4 times as fast. Architects call this number cycles per instruction (CPI), and lowering it is one of their main jobs.

</details>

## Part 3: Instruction set or implementation?

Say which of these belong to the **instruction set** (what a programmer can count on) and which to the **implementation** (how this particular CPU does it): what ADD does to A; how many ticks ADD takes; that SUB sets the carry flag when no borrow was needed; that the fetch takes two ticks.

<details>
<summary>Check your answer</summary>

What ADD does to A, and SUB's carry rule, are the instruction set: every tiny CPU must do them the same way, or programs would break. ADD's tick count and the two-tick fetch are the implementation: designs 1 and 2 differ in them, and programs still work. Real CPUs keep that line too, which is why one program runs on many different chips.

</details>
