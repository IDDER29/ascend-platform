Every program you've run on the tiny CPU ended by showing a number on the display. That display is the CPU's only connection to the outside world. Real computers have keyboards, screens, disks and networks, and they all use the same few ideas.

By the end you'll be able to explain how a number leaves the CPU, how one gets in, and how a program notices that something outside has happened.

## Output is a register with wires outside

The tiny CPU's display is driven by the <b>output register</b>. OUT copies A into it over the bus, like any other register load. What's different is where its wires go. They don't lead back to the bus. They lead to the display, which shows whatever byte the register holds until the next OUT replaces it.

<KeyIdea>Output is a register whose wires leave the CPU. Input is the reverse: wires from outside that the CPU can read.</KeyIdea>

## Devices at addresses

The tiny CPU has an instruction just for output. Most CPUs don't add a new instruction for every device. Instead, a device is wired so that it answers at a memory address. This is called <b>memory-mapped I/O</b>:

- Reading the device's address reads from the device: switches, a keyboard, a sensor.
- Writing to it sends a value to the device: a screen, a speaker, a network card.

The CPU doesn't know the difference. It runs an ordinary load or store, and the address decides whether the byte comes from memory or from a device.

Some CPUs, including x86, also have <b>port I/O</b>: separate in and out instructions that talk to a separate set of device addresses. It's the same idea with a second address space.

## Noticing a device: polling and interrupts

A key gets pressed at a moment the program can't predict. There are two ways to notice it.

- <b>Polling</b>: the program keeps reading the device's address in a loop, asking "anything yet?". It's simple, but the CPU is busy doing nothing useful while it waits.
- <b>Interrupts</b>: the device sends a signal on a dedicated wire. The CPU finishes its current instruction, saves where it was, and jumps to a piece of code called an <b>interrupt handler</b>. When the handler is done, the CPU jumps back to where it stopped.

An interrupt is a jump that the outside world causes, not the program. Your keyboard, your network card and the timer that lets an operating system share the CPU between programs all work this way.

<KeyIdea>Polling: the program keeps asking. Interrupts: the device taps the CPU on the shoulder.</KeyIdea>

The tiny CPU has neither input nor interrupts. It's kept small on purpose, so you can see every part. A real computer has the same pieces plus these: a register or address for each device, and a way for devices to interrupt.
