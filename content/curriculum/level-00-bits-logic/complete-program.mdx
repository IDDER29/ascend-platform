This lesson puts the whole course together in one program: a loop, memory, arithmetic, output and a subroutine. The program itself is short. What matters is how it's planned, written and checked.

By the end you'll be able to plan a small program, write it with comments, and change it safely.

## The task

Boxes 0x80 to 0x84 hold five scores: 3, 1, 4, 1 and 5. The program should show each score doubled, then the total of the doubled scores, and also keep that total in box 0x90.

The expected result, worked out by hand first: 6, 2, 8, 2, 10, and a total of 28.

## Plan it first

Before any instruction, decide what each register and box is for. Writing it down is what keeps the program readable later.

<KeyIdea>Plan the registers before the instructions. A program is easy to read when every register has one job.</KeyIdea>

## The program

Each block has a comment saying what it does. Run it, then step through one pass of the loop and check it against the plan.

<TinyCpu2 caption='Double each score, then show the total' programJson='["; Double each score, show it, and show the total.", "LDI R2, 0x80      ; R2 points at the first score", "LDI R3, 5         ; R3 counts the scores left", "LDI R1, 0         ; R1 is the running total", "next: LDR R0, [R2] ; R0 = this score", "CALL double", "OUT R0", "ADD R1, R0", "INC R2", "DEC R3", "JNZ next", "OUT R1", "STA R1, [0x90]", "HALT", "double: ADD R0, R0 ; R0 = R0 + R0", "RET"]' dataJson='{"128":3,"129":1,"130":4,"131":1,"132":5}' />

It shows 6, 2, 8, 2, 10 and 28, and leaves 28 in box 0x90. The comments take no space: the program is 15 instructions, from 0x00 to 0x1C, with `next` at 0x06 and `double` at 0x1A.

## Change it

Programs change. Box 0x85 now holds a sixth score, 9. Change the program so it handles six scores. It should show 6, 2, 8, 2, 10, 18 and then the total, 46.

<details>
<summary>Check your answer</summary>

Only one line changes: `LDI R3, 6`. The loop walks the scores with the pointer R2 until the count reaches zero, so nothing else depends on how many scores there are. That's what the plan bought you: a change in one place, with no surprises elsewhere.

</details>

<KeyIdea>Plan, comment, then check against a result worked out by hand. That's how a program stays correct as it changes.</KeyIdea>
