In the last course you saw that a pattern of bits means nothing until two sides agree on a code. Text is the most important code there is. Every letter you've read on this page arrived as bytes and was turned back into letters by a shared agreement.

By the end you'll be able to tell a character from the bytes that store it, read a few ASCII codes, and work out how many bytes a piece of text really takes.

## ASCII: one byte, one letter

The first widely shared code for text was <b>ASCII</b>, from 1963. It gives each of 128 characters a number from 0 to 127: the English letters, digits, punctuation, the space, and some control codes such as a new line. 128 numbers fit in 7 bits, so every ASCII character fits in one byte with a bit to spare.

Two patterns are worth noticing. The letters are in order, so B is A + 1. And a lowercase letter is its capital plus 32, which is one bit: 0100 0001 is A and 0110 0001 is a. The digit 0 is not the number 0: it is the character with code 48.

## Three things, not one

ASCII has no é, no ñ, no Chinese or Arabic, no emoji. <b>Unicode</b> fixes that by giving every character in every writing system its own number, called a <b>code point</b>, written like U+00E9. There are over a million possible code points, far more than one byte can hold.

That forces a distinction that ASCII let us ignore. For any character there are three separate things:

<TruthTable caption='Character, code point, bytes' rowsJson='[["character", "code point", "UTF-8 bytes"], ["A", "U+0041 (65)", "41"], ["é", "U+00E9 (233)", "C3 A9"], ["€", "U+20AC (8364)", "E2 82 AC"], ["😀", "U+1F600 (128512)", "F0 9F 98 80"]]' />

The character is what you see. The code point is the number Unicode gives it. The bytes are how that number is stored, and that depends on the <b>encoding</b>.

<KeyIdea>A character is not a byte. It is a symbol, with a number, stored as one or more bytes.</KeyIdea>

## UTF-8: one to four bytes

<b>UTF-8</b> is the encoding almost the whole web uses. Its rule is simple to state:

- Code points 0 to 127 (all of ASCII) take <b>one byte</b>, exactly as in ASCII.
- Bigger code points take <b>two, three or four bytes</b>.

So every old ASCII file is already valid UTF-8, which is a big part of why it won. The bytes of a longer character are easy to spot: the first byte starts with 110, 1110 or 11110 (saying how many bytes follow), and each byte after it starts with 10.

That means text length has two answers. The word "café" has four characters but five bytes: 63 61 66 for c, a, f, then C3 A9 for é. A program that counts bytes and a person who counts letters will disagree.

## When text turns to garbage

If you've ever seen "cafÃ©" where "café" should be, you've seen the codebook problem from the last course. The bytes C3 A9 were written as UTF-8 but read by a program that assumed one byte per character, using an older code where C3 is Ã and A9 is ©. Not one bit was damaged. The reader used the wrong code.

<KeyIdea>Text bytes only mean something together with their encoding. When text looks broken, ask which encoding wrote it and which one read it.</KeyIdea>
