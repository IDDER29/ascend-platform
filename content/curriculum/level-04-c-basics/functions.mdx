In Foundations you saw functions from the machine's side: a call pushes a return address, the function gets a frame on the stack, and its result comes back in a register. Now you'll write them the way C programmers do, and meet the two rules that cause most beginner confusion.

## Declare, define, call

A function has a name, the parameters it takes, and the type of value it returns:

<CRun program="c-basics/functions-square" caption='One function, called three times' predict />

<details>
<summary>Check your answer</summary>

`16 36 16`. `square(4)` is 16, so `a` is 16. `square(a - 10)` is `square(6)`, which is 36. `square(square(2))` works inside out: `square(2)` is 4, and `square(4)` is 16.

</details>

Three parts to notice:

- **The declaration** (`int square(int n);`, called a **prototype**) tells the compiler the function exists, what it takes and what it returns. It ends with a semicolon and has no body.
- **The definition** (`int square(int n) { ... }`) is the function itself. Here it comes after `main`, which is fine because the prototype came first.
- **The call** (`square(4)`) evaluates the argument, runs the body with `n` set to it, and becomes the value after `return`.

C reads a file from top to bottom. If `main` called `square` before any declaration of it, gcc would stop with an error, because it can't check the call against a function it hasn't seen. Either put the prototype first, or define the function above its callers. Larger programs put prototypes in header files, which you'll meet later.

A function that returns nothing has the return type `void`, and a function that takes nothing says so with `(void)`, as `int main(void)` does.

## Arguments are copies

What does this print?

<CRun program="c-basics/functions-by-value" caption='Can a function reset your variable?' predict />

<details>
<summary>Check your answer</summary>

`inside:  n = 0`, then `after try_to_reset: score = 42`, then `after reset:        score = 0`.

C passes arguments **by value**. When `main` calls `try_to_reset(score)`, the value 42 is copied into a brand new variable `n` in `try_to_reset`'s frame. Setting `n` to 0 changes the copy, and the copy disappears when the function returns. `score` was never touched.

The second version works because it doesn't try to change anything from the inside: it *returns* the new value, and `main` assigns it with `score = reset(score);`.

</details>

<KeyIdea>A parameter is a new variable holding a copy of the argument. To give a caller a new value, return it; changing a caller's variable directly needs a pointer, which comes in The C Language.</KeyIdea>

## Every path must return

This function should return 1 for positive numbers, -1 for negative ones and 0 for zero. It has a bug. We compiled it with `-Werror=return-type`, which turns that one warning into an error so the broken program can't run.

<CRun program="c-basics/functions-missing-return" caption='A function with a missing case' />

When `x` is 0, neither `return` runs and the function falls off its end. Using the value of such a call is **undefined behaviour**: C makes no promise at all about what you get, and a different compiler or optimisation setting can give a different answer. gcc catches it, but only if you turn warnings on with `-Wall`.

Fix the function so every path returns a value.

<details>
<summary>Check your answer</summary>

Add the missing case, usually as a final `return` after the `if` chain:

```c
#include <stdio.h>

int sign(int x) {
    if (x > 0) {
        return 1;
    } else if (x < 0) {
        return -1;
    }
    return 0;
}

int main(void) {
    printf("%d %d %d\n", sign(5), sign(-3), sign(0));
    return 0;
}
```

It prints `1 -1 0`. A final `return` outside every `if` is the simplest way to be sure no path is missed.

</details>

## Small functions, good names

Splitting work into functions isn't only about reuse. A function with a clear name turns a block of code into one readable step:

```c
#include <stdio.h>

int is_leap_year(int year) {
    return (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
}

int days_in_february(int year) {
    return is_leap_year(year) ? 29 : 28;
}

int main(void) {
    printf("%d %d %d\n", days_in_february(2024), days_in_february(1900), days_in_february(2000));
    return 0;
}
```

This prints `29 28 29`. Each function does one thing, takes everything it needs as parameters, and returns its answer, so you can test it on its own. Functions that only read their parameters and return a result, like these, are the easiest to get right.

Predict what `days_in_february(2100)` returns, and say which rule decides it.

<details>
<summary>Check your answer</summary>

28. 2100 is divisible by 4 but also by 100, and not by 400, so `is_leap_year` returns 0 (false). Like 1900, it's a century year that isn't a leap year.

</details>
