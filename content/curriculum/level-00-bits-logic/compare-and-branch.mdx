A program that only runs straight through can't decide anything. Deciding takes two steps: a **compare**, which sets the Z flag, and a **conditional branch**, which jumps or doesn't depending on Z.

By the end you'll be able to write ifs and if/elses in assembly, and know exactly what version 2 can compare.

## Compare, then branch

<TruthTable caption='Compares and branches in version 2' rowsJson='[["instruction", "does"], ["CMP Rd, Rs", "Z = 1 if Rd equals Rs, else Z = 0"], ["CMPI Rd, n", "Z = 1 if Rd equals n, else Z = 0"], ["JZ label", "jump to label if Z is 1"], ["JNZ label", "jump to label if Z is 0"], ["JMP label", "always jump to label"]]' />

A compare changes nothing but Z. The registers keep their values, so the next instructions can still use them. A label such as `yes:` names an address, and the assembler turns `JZ yes` into a jump to it.

## An if/else in assembly

This program reads box 0x80. If it holds 7 it shows 1, otherwise it shows 0. Box 0x80 holds 7 here; step through it and watch the program counter jump.

<TinyCpu2 caption='If the box holds 7, show 1, else 0' programJson='["LDA R0, [128]","CMPI R0, 7","JZ yes","LDI R1, 0","JMP done","yes: LDI R1, 1","done: OUT R1","HALT"]' dataJson='{"128":7}' />

The shape is always the same:

1. Compare.
2. Branch to the "then" part if the test passed.
3. Otherwise fall through into the "else" part, which ends with a JMP over the "then" part.
4. Both paths meet again at a label after the if.

Forget the JMP at step 3, and the else part runs straight on into the then part: both run.

<KeyIdea>An if is a compare and a branch around code. An if/else adds one JMP, so that only one of the two parts runs.</KeyIdea>

## Only equal or not

Version 2's compares test one thing: equality. There's no carry flag and no sign flag, so there's no instruction for "is R0 greater than R1". Real CPUs have those, and branches for every kind of comparison; this one keeps the instruction set small.

Testing for zero is the easiest case. CMPI R0, 0 sets Z when R0 is 0. And since arithmetic instructions set Z too, a DEC or SUB can often be followed by a branch straight away, with no compare at all. The next lesson's loops are built on exactly that.

<KeyIdea>On version 2, a branch can only ask "was the last result zero?" or "were these equal?". Everything else is built from those.</KeyIdea>
