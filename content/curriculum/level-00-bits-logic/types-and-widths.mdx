In the tiny language every value is one byte, read as a number from 0 to 255. Real languages offer many kinds of values, called <b>types</b>, and the choice matters.

By the end you'll be able to say what a type tells the computer, give the common C sizes, and predict what happens when a value doesn't fit.

## What a type says

A type tells the computer two things:

- its <b>width</b>: how many bits the value takes up;
- its <b>reading</b>: how to interpret those bits (unsigned number, signed number, character, fraction).

The bits don't say which. You saw this in Binary & Data: one byte can be 255, -1, a letter or part of a colour. A type is the program's promise about which reading it means.

On a typical 64-bit Linux machine, C's integer types have these widths. This program prints them:

```c
#include <stdio.h>

int main(void) {
    printf("%zu %zu %zu %zu\n", sizeof(char), sizeof(short), sizeof(int), sizeof(long));
    unsigned char c = 250;
    c = c + 10;
    printf("%d\n", c);
    return 0;
}
```

```
1 2 4 8
4
```

<TruthTable caption='Common C integer types (64-bit Linux)' rowsJson='[["type", "bytes", "bits", "unsigned range"], ["char", "1", "8", "0 to 255"], ["short", "2", "16", "0 to 65,535"], ["int", "4", "32", "0 to about 4.3 billion"], ["long", "8", "64", "0 to about 18 billion billion"]]' />

These sizes are what most machines use today, but C only guarantees minimums: an int is at least 16 bits. That's why programs that care use `sizeof`, as above, instead of assuming.

## When a value doesn't fit

The second line of output above is the interesting one. An unsigned char holds 0 to 255; 250 + 10 is 260, which needs 9 bits, so the top bit is dropped and 4 is left. That's the overflow you met in Binary & Data, now attached to a type.

The tiny language has the same rule, since every variable is one byte. Make x end at exactly 0 by changing one number:

`x = x + 56;`. 200 + 56 is 256, one more than a byte can hold, so it wraps to 0. A wider type would have held 256 without any surprise.

## Same bits, different type

Reading is the other half of a type. This C program copies one byte into a signed char:

```c
#include <stdio.h>

int main(void) {
    unsigned char u = 255;
    signed char s = (signed char)u;
    printf("%d %d\n", u, s);
    return 0;
}
```

```
255 -1
```

Both variables hold the bits 1111 1111. The unsigned type reads them as 255; the signed type, using two's complement, as -1. Nothing changed in memory: only the promise about how to read it.

<KeyIdea>A type is a width and a reading. Choose it for the largest value you'll ever need, and the meaning you want the bits to have.</KeyIdea>
