Four puzzles for the tiny CPU, version 2. Each one has a goal, checked when your program halts, and a starting program that doesn't meet it yet. Edit the program, press Run, and read the line at the bottom.

Data lives at 0x80 and up (128 and up in decimal). The listing on the left shows what your program assembled to.

## Puzzle 1: Add two numbers

Boxes 0x80 and 0x81 hold two numbers. Put their sum in box 0x82.

<TinyCpu2 editable caption='Puzzle 1: the sum goes in 0x82' programJson='["LDA R0, [0x80]", "HALT"]' dataJson='{"128":19,"129":23}' goalJson='{"mem":{"130":42}}' />

<details>
<summary>Check your answer</summary>

```
LDA R0, [0x80]
LDA R1, [0x81]
ADD R0, R1
STA R0, [0x82]
HALT
```

Two loads, an add, a store. The ALU only works on registers, so both numbers have to come out of memory first and the sum has to go back in.

</details>

## Puzzle 2: Copy four bytes

Copy the four bytes in 0x80 to 0x83 into 0x90 to 0x93, using a loop. You'll want an address in a register: `LDR R0, [R1]` reads the box whose address is in R1.

<TinyCpu2 editable caption='Puzzle 2: copy 0x80..0x83 to 0x90..0x93' programJson='["LDI R1, 0x80", "LDI R2, 0x90", "HALT"]' dataJson='{"128":5,"129":6,"130":7,"131":8}' goalJson='{"mem":{"144":5,"145":6,"146":7,"147":8}}' />

<details>
<summary>Check your answer</summary>

```
LDI R1, 0x80    ; where to read
LDI R2, 0x90    ; where to write
LDI R3, 4       ; how many
loop: LDR R0, [R1]
STR R0, [R2]
INC R1
INC R2
DEC R3
JNZ loop
HALT
```

R1 and R2 are pointers: they hold addresses, and moving on is just adding 1. This is exactly what a loop over an array becomes in any language.

</details>

## Puzzle 3: Count down

Output 5, 4, 3, 2, 1, and then stop: no 0.

<TinyCpu2 editable caption='Puzzle 3: output 5, 4, 3, 2, 1' programJson='["LDI R0, 5", "OUT R0", "HALT"]' goalJson='{"out":[5,4,3,2,1]}' />

<details>
<summary>Check your answer</summary>

```
LDI R0, 5
loop: OUT R0
DEC R0
JNZ loop
HALT
```

Output first, then count down, then test. With the OUT after the DEC, you'd get 4, 3, 2, 1 and miss the 5; with the test before the DEC, you'd also output 0. Where the test sits decides the first and last trip round.

</details>

## Puzzle 4: The larger of two

Output the larger of the numbers in 0x80 and 0x81. The catch: this CPU can only test for equality. There's no "greater than" branch.

<TinyCpu2 editable caption='Puzzle 4: output the larger number' programJson='["LDA R0, [0x80]", "OUT R0", "HALT"]' dataJson='{"128":9,"129":14}' goalJson='{"out":[14]}' />

<details>
<summary>Check your answer</summary>

Count both down together; whichever reaches zero first was the smaller.

```
LDA R2, [0x80]
LDA R3, [0x81]
loop: CMPI R2, 0
JZ second        ; the first ran out: the second is larger (or equal)
CMPI R3, 0
JZ first         ; the second ran out: the first is larger
DEC R2
DEC R3
JMP loop
first: LDA R0, [0x80]
OUT R0
HALT
second: LDA R0, [0x81]
OUT R0
HALT
```

Try it with the numbers swapped, and with two equal numbers: it still works. But it takes about 7 steps per count, so with 200 and 199 it would need about 1,400 steps; the simulator stops at 1,000. Real CPUs have a carry or sign flag for exactly this reason: comparing by subtracting once is far faster than counting.

</details>

<KeyIdea>Every puzzle is one idea: a register holding an address, a counter, or a test. Programs are those ideas, combined.</KeyIdea>
